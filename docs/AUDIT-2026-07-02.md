# Codebase + Planning Audit — 2026-07-02

Full-repo audit on branch `feat/phase-56-foundation` (cross-checked against `fc1/prod` and running containers where relevant). Five parallel review passes: farm-agent Python port, legacy Node alerter + whisper, fc-core + mission-control, GSD planning docs, infra/scripts/secrets.

**Honest one-paragraph verdict:** the execution-layer engineering is genuinely good for a one-operator production farm — parameterized SQL everywhere, env-only secrets, CAS-guarded state machines, honest porting notes, 650+ tests, real incident archaeology in comments. The problems cluster in exactly two places the project's own lessons predict: **wiring seams that unit tests don't catch** (the Python port has a whole cluster of silent post-farmer-YES failures, a dead fidelity gate, and a missing volume mount), and **drift between what's deployed and what's committed** (the decay_tau reboot landmine is still armed in the bridge, the feather calibration lives only on `fc1/prod`, the deployed backup script silently skips the Signal-identity volume). The planning phase-level paper trail is trustworthy; the status-summary layer (STATE.md, ROADMAP tables, MILESTONES.md, HANDOVER.md) is not.

## 1. farm-agent (Python port, v1.12) — the active work

**Health:** architecture coherent (DI factories, never-throws envelopes, CAS SQL guards, phone masking, no SQL injection, no secrets). 652 tests, strong at module level — but the suite validates *assumed* shapes, not real seams; no end-to-end handle→extract→confirm→commit test. The port is roughly bottom-half complete: Signal I/O, capture, gate, extractor module, confirm FSM, farmOS write stack are solid; nothing on top is wired.

**Critical / High** (beyond Top-10 items 2, 5, 6, 7):

- **H4 — receive loop can die silently forever.** `extract_source`/`is_whitelisted` run bare inside the envelope for-loop; one non-dict envelope raises out of `tick()` and kills the background task. Nothing observes the task (no done-callback), so the daemon looks up with a dead inbound loop — exactly what the module docstring claims to prevent. `farm_agent/signal_io/receive_loop.py:87-128`.

**Medium:**

- **M1 — extractor + confirm routing not wired into the live pipeline.** `boot.py` builds and passes an extractor that `pipeline.py:139` accepts and never uses; `route_confirm_reply` has no production caller. Today's daemon is a capture recorder + two watchdogs. Possibly phased-by-design (63/64), but it's unmarked dead wiring that reads as complete.
- **M2 — farmer EDIT is a silent no-op.** Bumps the edit counter, calls a stub, sends no reply. The stub says "Phase 62" — Phase 62 is closed. `confirm/dispatch.py:339-367`.
- **M3 — confirm watchdog has no origin guard.** It nudges/expires Node-owned drafts on the shared DB during coexistence (commit path was guarded in 62; confirm path wasn't). Known v1.13 candidate, but it's live-risk today because the loop starts unconditionally in boot.
- **M4 — Toronto TZ default resurrected**: `tenant.py:392` falls back to `America/Toronto`; same in farmos-agent (`farmos_agent_node.py:67`, `telemetry_query.py:701`). Compose currently papers over it.
- **M5 — farmos-agent DB connection has no rollback/reconnect**: one failed query leaves psycopg2 in aborted-transaction state and every subsequent 06:00 daily report fails silently until container restart.
- **M6 — commit watchdog passes no `ctx`** → observations and seeding sessions commit **without photos**, silently; no `audit_logger` either, so all ported audit hooks are dead. `commit_watchdog.py:729`.
- **M7 — dead config + dead cost tracking**: `rh_target`, `rh_band`, `pi_offline_min`, `heartbeat_hour`, `log_level` etc. parsed and consumed nowhere (Phase 63 scope, but `log_level` is just dead — boot hardcodes INFO). Token-usage columns created by migrations are never written by the Python capture path — `v_llm_cost_daily` will undercount once Python extracts.
- **M8 — strain confirm leaves `needs_review_reason='strain_unknown_pending_confirm'`** and persists no approved marker; a later `commit_failed` re-enters the strain intercept instead of the standard flow.

**Low:** stale `TODO(Phase 60)` with `last_bot_outbound=None` hardcoded (all short acks hit Haiku, wasted spend); blocking `write_bytes`/PIL in async paths; commit-time `time.time()` fallback timestamps misdate backfill; `mark_failed` sets `committed_at=NOW()` on failure; `FARMOS_URL` code default is the dev IP (Phase-65 cutover footgun); signal handlers registered only after full boot.
