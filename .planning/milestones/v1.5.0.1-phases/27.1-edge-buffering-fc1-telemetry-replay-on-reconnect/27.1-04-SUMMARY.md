## Gotchas encountered

1. **`install -d` ExecStartPre failed on first restart** with "cannot change owner and permissions" — recovered by manually running `sudo mkdir -p /var/lib/fc-core && sudo chown ubuntu:ubuntu /var/lib/fc-core`. Cause unclear; possibly a transient permissions race during systemd's unit reload. Subsequent restarts work fine.
2. **fc1's local git checkout had diverged** from origin/fc1/prod (6 stale commits from old fc1/prod history that we force-pushed away from earlier in the day). Resolved with `git reset --hard origin/fc1/prod` on both `~/mushroom_farm_ws/src` and `~/mushroom_farm_ws/mushy-repo`. No data lost — divergent commits were content-equivalent to main's history.
3. **First colcon build failed** on stale install dir (buffered_topics.yaml symlink-install couldn't find target). Resolved with `rm -rf build/fc_core install/fc_core` + clean rebuild without `--symlink-install`.
4. **Original Plan 04 was written for SSH-via-Tailscale**; the actual deploy used SSH-over-WG (172.16.10.5). Plan instructions still readable but path-references obsolete.

## SD card wear concern (open)

fc1 is now booting from a microSD (not USB-SSD as we'd planned). fc_buffer writes to /var/lib/fc-core/buffer.sqlite via SQLite WAL — every telemetry message is a small write. SD card wear is a real concern for sustained operation. **Mitigation:** USB-SSD migration is a separate work item (user already procuring hardware). Until then, SD-card lifetime is the silent risk.
