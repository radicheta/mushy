This task has two parts: diagnosis (on Pi via SSH) and fix.

**PREREQUISITE:** Phase 09 must be complete — the Pi must be reachable over Tailscale.
If the Pi is unreachable, this plan cannot proceed. Document the blocker and stop.

**Part A: Diagnose live config on Pi (SSH)**

1. SSH to fc1 Pi and inspect the live CycloneDDS config:
   ```bash
   ssh ubuntu@100.96.239.75  # fc1 Pi Tailscale IP
   # Check what CYCLONEDDS_URI points to
   systemctl show fc-core.service -p Environment | grep CYCLONEDDS
   cat /etc/cyclonedds.xml  # or whatever path CYCLONEDDS_URI resolves to
   ```

2. Search for the phantom peer IP in the live config:
   ```bash
   grep -r "192.168.1.193" /etc/cyclonedds* 2>/dev/null
   ```

3. Check current error rate:
   ```bash
   journalctl -u fc-core.service --since "5 minutes ago" | grep 192.168.1.193 | wc -l
   ```

**Part B: Apply fix based on diagnosis**

**If `192.168.1.193` IS in the live Pi config (config drift from repo):**
- The live `/etc/cyclonedds.xml` has diverged from the repo-tracked
  `scripts/pi-deploy/cyclonedds.xml`. Remove the `192.168.1.193` peer entry
  from the live file on the Pi.
- Also update `scripts/pi-deploy/cyclonedds.xml` in the repo if it needs to
  change the network interface from `wg0` to `tailscale0` to match the current
  VPN setup (Phase 09 switched from WireGuard to Tailscale). Check what
  interface the live Pi config uses.

**If `192.168.1.193` is NOT in the live Pi config (stale DDS discovery cache):**
- The phantom peer is in CycloneDDS in-memory discovery state from a pre-VPN
  LAN session. Restarting fc-core.service clears it:
  ```bash
  sudo systemctl restart fc-core.service
  ```
- After restart, verify the errors are gone:
  ```bash
  sleep 30 && journalctl -u fc-core.service --since "30 seconds ago" | grep 192.168.1.193
  ```
  If zero matches, the fix worked — commit the current state.

**If phantom peer RETURNS after restart (fallback D-06):**
- Add `LeaseDuration` tuning to the Pi-side CycloneDDS config to shorten peer
  expiry. Update `scripts/pi-deploy/cyclonedds.xml` in the repo:
  ```xml
  <Discovery>
      <LeaseDuration>5 s</LeaseDuration>
      <Peers>
          <Peer address="100.96.10.66"/>   <!-- elder-plops Tailscale IP -->
          <Peer address="100.96.239.75"/>  <!-- FC-1 Pi Tailscale IP -->
      </Peers>
  </Discovery>
  ```
  NOTE: The peer addresses may need updating from WireGuard IPs (172.16.10.x)
  to Tailscale IPs (100.96.x.x) if Phase 09 changed the VPN. Check the live
  config for the current correct addresses.
- Deploy the updated config to the Pi via `fc1/prod` branch + `deploy.sh`,
  then restart fc-core.service.

**In all cases:** After applying the fix, verify the network interface in the
CycloneDDS config matches the current VPN interface on the Pi. Phase 09 may
have changed from `wg0` (WireGuard) to `tailscale0` (Tailscale). If the repo
config says `wg0` but the Pi uses `tailscale0`, update `scripts/pi-deploy/cyclonedds.xml`
to match. The interface name must be correct for unicast DDS to work.

Deploy any repo changes via: commit to repo, push to `fc1/prod`, run deploy.sh
on Pi (or let fc-update.service pick it up on next boot).
