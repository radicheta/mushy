  <how-to-verify>
  **Pre-condition:** MiFi is powered on, has 4G signal, and you know its SSID and passphrase.

  **Step 1 — Connect Pi wlan0 to MiFi:**
  From an SSH session over the existing LAN connection (10.68.155.53), configure
  wlan0 to associate with the MiFi. Use netplan (matching the Pi's existing
  /etc/netplan/ setup):

  ```bash
  # On Pi via existing LAN SSH — do NOT disconnect the LAN yet
  sudo tee /etc/netplan/60-mifi-wifi.yaml > /dev/null << 'EOF'
  network:
    version: 2
    wifis:
      wlan0:
        dhcp4: true
        access-points:
          "MIFI_SSID_HERE":
            password: "MIFI_PASSPHRASE_HERE"
  EOF
  sudo chmod 600 /etc/netplan/60-mifi-wifi.yaml
  sudo netplan apply
  ```

  Replace MIFI_SSID_HERE and MIFI_PASSPHRASE_HERE with the actual values.
  Wait ~15 seconds, then check:

  ```bash
  ip addr show wlan0
  # Expected: wlan0 has an inet address from MiFi's DHCP (e.g. 192.168.0.x)
  ```

  **Step 2 — Verify internet over wlan0:**
  ```bash
  curl --interface wlan0 -s https://checkip.amazonaws.com
  # Expected: returns a public IP (the MiFi's 4G WAN IP)
  ```

  **Step 3 — Verify Tailscale is up over cellular:**
  ```bash
  tailscale status
  # Expected: fc1-ts shows as connected, elder-plops visible
  tailscale ping 100.96.10.66
  # Expected: pong from 100.96.10.66 (elder-plops)
  ```

  **Step 4 — Verify ROS topic from elder-plops (farm location):**
  On elder-plops (farm location):
  ```bash
  ros2 topic echo /fc1/humidity --once
  # Expected: returns a humidity reading within 5 seconds
  ```
  Record reading and timestamp. This satisfies success criterion 1, location 1 (farm).

  **IMPORTANT — NEVER disable interfaces over SSH (memory feedback_no_interface_down.md).
  Do not run `ip link set wlan0 down` or `ip link set eth0 down` remotely.**
  </how-to-verify>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi wlan0 → MiFi LAN | Pi gets DHCP from MiFi; MiFi LAN is trusted (physically secured) |
| MiFi WAN → cellular carrier | Untrusted internet transit; all ROS/DDS traffic encrypted by Tailscale end-to-end |
| elder-plops → fc1 over Tailscale | Encrypted WireGuard tunnel managed by Tailscale coordination server |
| MiFi admin UI → Pi subnet | MiFi's admin interface is reachable from Pi's wlan0; risk: unauthorized config changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02-01 | Interception (MiTM) | ROS DDS traffic over cellular | mitigate | Tailscale end-to-end WireGuard encryption is already in place (Phase 06). All DDS unicast goes through tailscale0 — no plaintext ROS traffic on cellular. |
| T-09-02-02 | Spoofing | DNS hijack on cellular carrier network | accept | No DNS-sensitive operations in the ROS data path. Tailscale uses hardcoded Tailscale coordination server cert. Low risk. |
| T-09-02-03 | Information Disclosure | MiFi admin UI exposed on Pi's wlan0 subnet | mitigate | MiFi admin UI is typically 192.168.x.1 on the MiFi LAN. Pi does not run any services that proxy or expose the MiFi admin. Access requires physical proximity or LAN access. Acceptable for a single-device farm network. |
| T-09-02-04 | Denial of Service | Cellular carrier throttles or blocks UDP (Tailscale uses UDP 41641) | accept | Tailscale falls back to DERP relay over HTTPS if UDP is blocked. Some latency increase but connectivity maintained. D-09 accepts this: no fc_core changes needed. |
| T-09-02-05 | Tampering | netplan 60-mifi-wifi.yaml contains MiFi passphrase in plaintext | accept | File is chmod 600, accessible only by root/ubuntu. Farm Pi is in a physically secured area. For a production grower deployment this is acceptable; secret management is a future concern. |
| T-09-02-06 | Elevation of Privilege | deploy.sh SSH over Tailscale reaching Pi as ubuntu | mitigate | SSH key auth only (no password). ubuntu account is non-root; sudo required for systemctl commands. Tailscale device trust enforces identity. |
</threat_model>
