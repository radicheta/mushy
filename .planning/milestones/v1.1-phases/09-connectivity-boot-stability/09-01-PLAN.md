<objective>
Fix the cold-boot race where fc-core.service starts before tailscale0 is
available, causing rmw_create_node to fail with "failed to create domain /
tailscale0 interface not available yet" and triggering ~4 automatic restarts
per boot.

Purpose: TDEBT-03 — eliminate restart loops on cold boot so the Pi is
trustworthy and unattended at the farm. This is the prerequisite for the
30-second Mission Control dashboard criterion (success criterion 4).

Output: Updated fc-core.service checked into fc1/prod and deployed to the
Pi via deploy.sh. Zero restarts on next cold boot.
</objective>

3. In [Service], add the following ExecStartPre= directive BEFORE the
   existing ExecStart= line (inline shell — no separate script file per D-07):

     ExecStartPre=/bin/bash -c '\
       echo "fc-core: waiting for tailscale0 interface..."; \
       for i in $(seq 1 30); do \
         if ip link show tailscale0 > /dev/null 2>&1; then \
           echo "fc-core: tailscale0 ready (attempt $i)"; \
           exit 0; \
         fi; \
         sleep 1; \
       done; \
       echo "fc-core: tailscale0 did not appear after 30s — aborting start"; \
       exit 1'

   Rationale for the poll (D-06 Claude's discretion):
   - 1-second poll interval, max 30 iterations = 30s ceiling
   - `ip link show tailscale0` checks interface existence without requiring
     Tailscale to have established peers (that happens asynchronously and
     does NOT need to be waited for here — CycloneDDS handles peer discovery)
   - exit 1 after timeout causes systemd to see ExecStartPre fail; fc-core
     will NOT start and Restart=on-failure will retry after RestartSec=5,
     which is acceptable as a true failure (e.g., tailscaled never started)
     rather than the current race (tailscaled started but interface not yet
     configured)

   The final [Unit] section MUST look exactly like this:

     [Unit]

     Wants=network-online.target fc-update.service tailscaled.service

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi boot environment → ExecStartPre shell | Script runs as root (systemd Service User= is ubuntu, but ExecStartPre runs before User= drop? — actually User=ubuntu applies to ExecStartPre too in simple services) |
| Pi local filesystem → /etc/systemd/system/ | Only ubuntu + sudo can write unit files; deploy.sh uses SSH key auth |
| elder-plops SSH → fc1 Pi | SSH over Tailscale encrypted tunnel; no plaintext credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01-01 | Tampering | ExecStartPre shell script body | accept | Script is a read-only poll of `ip link show` — no external input, no env var injection; the only mutable input is kernel interface table (trusted). User=ubuntu limits blast radius. |
| T-09-01-02 | Elevation of Privilege | ExecStartPre running as ubuntu | accept | User=ubuntu in [Service] applies to all Exec* directives. ubuntu is in gpio+i2c groups but not full root. Systemd already enforces this; no additional hardening needed for a polling loop. |
| T-09-01-03 | Denial of Service | tailscale0 never appears → ExecStartPre exits 1 → restart loop | mitigate | 30s timeout + exit 1 is correct behavior: if tailscaled is broken, fc-core should not start. Restart=on-failure + RestartSec=5 provides backoff. Operators see it immediately in journalctl. |
| T-09-01-04 | Spoofing | Attacker creates fake tailscale0 interface on Pi LAN | accept | Physical access to Pi required. tailscaled owns tailscale0; it cannot be spoofed without root access. Farm is a trusted physical environment. |
| T-09-01-05 | Information Disclosure | deploy.sh SSH key exposed | mitigate | SSH key stored in user's ~/.ssh with 600 perms; deploy.sh uses fc1 alias (Tailscale host). All traffic encrypted by Tailscale. No passwords in scripts. |
</threat_model>
