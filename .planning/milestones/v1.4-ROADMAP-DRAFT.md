# v1.4 — Vision & Growth Insights (DRAFT)

**Status:** Draft. Not yet an active milestone. Promote with `/gsd:new-milestone v1.4`
once v1.3 closes (Phase 18 minimum; 19/20 may defer into v1.5).

**Narrative:** The farm sees itself grow. Continuous camera history, time-lapse
footage, ML-detected pinning and contamination events — routed through the
Signal alert pipeline built in Phase 17. Demo-able artifacts at every phase.

---

## Why now

v1.3 is infrastructure. Demoability matters for funding. The camera has been
live since v1.0 and CV is the highest-leverage thing we haven't monetized.
ComfyUI is already running on elder-plops, so ML inference is a near-zero-cost
addition architecturally — we just need the vision-agent wrapper and a workflow
JSON.

## Phases (proposed)

### Phase 21 — Camera history, continuous persistence

**Goal:** Every frame is archived with a timestamp queryable from Timescale.

- Decide persister architecture — recommended: dedicated `archivist` subscriber
  on elder-plops that holds a full-rate subscription, keeping Phase 12's
  idle-pulse gain for UI clients while archiving continuously.
- Create `snapshots` table in Timescale: `camera_id, captured_at, file_path, bytes`.
- Wire `saveSnapshot()` in bridge to insert rows (`src/mission-control/bridge/src/index.js:381`).
- Backfill: index existing on-disk snapshots from `/data/snapshots/fc1/`.

**Demoable output:** SQL query that returns a week of frame metadata. Not sexy alone, unblocks everything.

**Composes with:** 999.14 (supersedes it), 999.1 (edge-buffering pairs well if offline-tolerance becomes a requirement).

---

### Phase 22 — Timeline scrubber + farmer story view

**Goal:** Farmer can scrub hours/days of footage with sensor overlays on a phone.

- New route on bridge serving farmer-facing timeline (`/farmer/story` or similar).
- Time-indexed image viewer with hour/day jump controls.
- Overlay RH/CO₂/humidifier-state from existing Timescale history on the timeline axis.
- Light HTML/CSS/JS — same "no framework" rule as Phase 18.

**Demoable output:** farmer phone → "scrub back to last Tuesday 2am" → see frame + sensor trace. First screenshot for the deck.

**Composes with:** Phase 18 farmer dashboard (extends it), slice of 999.11.

---

### Phase 23 — Time-lapse composition

**Goal:** Daily and on-demand time-lapse mp4s generated automatically.

- ffmpeg pipeline triggered nightly (e.g. 00:30) that composes the previous day's
  frames into an mp4 with a sensible framerate and overlay (timestamp, RH).
- On-demand endpoint: `GET /timelapse?from=...&to=...` → streaming mp4.
- Storage policy: keep per-day mp4s forever; raw frames behind a retention window.

**Demoable output:** shareable mp4 clip. First tweet-able artifact, first pitch-deck video.

**Composes with:** 999.5.

---

### Phase 24 — ML vision events (pinning + contamination)

**Goal:** ComfyUI-backed detection writes events to Timescale and fires Signal alerts
for high-confidence contamination.

**Architecture:**
- New `vision-agent` container on elder-plops (sibling to alerter/bridge).
- Pulls unprocessed frames from the Phase 21 snapshot index.
- POSTs frame + workflow JSON to ComfyUI REST API.
- Writes detections to Timescale `vision_events` table (`event_type, camera_id, captured_at, confidence, metadata`).
- Routes high-confidence contamination events through the alerter's bridge-client
  path so they reach Signal alongside RH alerts.

**Model progression:**
- **Sub-phase 24a — Zero-shot baseline:** CLIP or Grounding DINO prompts
  (`"healthy oyster mushroom substrate"` vs `"green mold contamination"`,
  `"mushroom pin"` vs `"bare substrate"`). Proves the pipeline and produces
  a signal baseline against historical frames.
- **Sub-phase 24b — Segment + track:** SAM2 / Grounding-SAM to segment individual
  pins and track them across the time-lapse. Size-over-time = maturity proxy.
  This is the demo centerpiece.
- **Sub-phase 24c — Deferred to v1.5:** fine-tuned classifier once farmer has
  labeled a few hundred frames during v1.4.

**ComfyUI leverage:**
- Workflow JSON is swappable config — try new models without a redeploy.
- Node parameters become farmer-facing ops knobs ("tune sensitivity").
- Farmer or dev can iterate on workflows in the ComfyUI UI directly.

**Risk flags (must address, not defer):**
- False-positive contamination alerts erode trust built in Phase 17. Required:
  N-of-M debounce over multiple frames AND farmer confirm-before-alert loop
  for contamination severity ≥ threshold. Pinning events can auto-fire (less scary).
- ComfyUI uptime on elder-plops — currently dev-use; needs a "treat as prod" pass
  (systemd unit, restart policy, vision-agent health check with backpressure when
  ComfyUI is down).
- GPU contention if elder-plops is doing other ML work. Borrowed compute is
  available per operator decision 2026-04-19; not needed for zero-shot + SAM2.

**Demoable output:** Signal alert reading *"Pin detected on shelf 2, 10:42"* with a
thumbnail. Plus time-lapse overlaid with pin/contamination bounding boxes.
Headline artifact.

## Risks & open decisions

| Risk / Decision | Why it matters | Current thinking |
|---|---|---|
| Storage volume (continuous archive) | 24 KB/frame × 1 fps × 24h ≈ 2 GB/day per chamber. Outdoor log chamber could push this. | Retention policy in Phase 21 — raw frames maybe 14 days, time-lapse mp4 forever. |
| False-positive contamination alerts | Loss of farmer trust unwinds Phase 17 + all v1.3 trust work. | Debounce + confirm-before-alert; contamination-confidence threshold tunable. |
| ComfyUI as prod dependency | Dev-only today. | Phase 24 pre-gate: systemd + health check. Don't start 24 until this lands. |
| 4G bandwidth | fc1 over cellular; frames already trickle-rate when idle (Phase 12). | Persister runs on elder-plops side, not Pi — no additional Pi upstream traffic. Outdoor log chamber will need the same pattern. |

## Phase ordering rationale

21 → 22 → 23 → 24 is a strict dependency chain on data availability: 22 needs 21's
index, 23 needs 21's continuous frames, 24 needs 21's frame stream.

Each phase is independently demo-able, so funding review can happen after any
phase — 22 gives the first screenshot, 23 gives the first video, 24 gives the
first "AI" headline.
