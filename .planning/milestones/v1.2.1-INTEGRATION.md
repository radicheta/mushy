## Verify Checklist (per user questions)

1. **fc_controller → bridge sensor_health.** Topic `fc1/sensor_health`, msg `diagnostic_msgs/msg/DiagnosticStatus`, QoS depth=1, RELIABLE, KEEP_LAST, TRANSIENT_LOCAL on both sides. MATCH.
2. **Bridge WS → plugin.js health strip.** Bridge flattens `KeyValue[]` into `values{}` map; plugin reads `values.grace_elapsed_sec` / `grace_total_sec` (plugin.js:532–533, 541–542). Keys emitted by publisher (fc_controller.py:258–259) match keys consumed. MATCH.
3. **16.1 replay shim.** On `wss.on('connection')`, bridge immediately sends cached `lastSensorHealthBroadcast` to the new ws only (not via `broadcast()` — avoids re-sending to everyone). Plugin's `openHealthWs.onmessage` is the same code path used for live broadcasts, so cached delivery is indistinguishable from a fresh publish. CORRECT.
4. **E2E restart → 20s grace → OK flow.** fc_controller `__init__` sets `_boot_time` + `_warming_up=True`; `_grace_active()` returns True until buffer full AND 20s elapsed; first WARN publish at control_loop tick via `_warmup_signal_published` guard (one-shot). On grace exit, `_warming_up` flips and OK is published. TRANSIENT_LOCAL ensures bridge sees last WARN even if subscribed late; replay shim ensures browser sees it on reconnect. COMPLETE.
5. **E2E camera viewer → Feed live green.** MC viewer connects to MJPEG → bridge increments `mjpegClients` → creates `cameraSubscription` → fc_camera's 1 Hz `_graph_poll` detects new subscriber via `count_subscribers('fc1/camera/compressed')` → frames flow → `lastFrameTime` updates → `/health` reports `last_frame_age_sec < 10` AND `subscribed=true` → plugin.js:595 sets Feed/Camera feed lights green. COMPLETE.
6. **makeStatusLight signature stability.** Defined Phase 14 at plugin.js:70 as `(parentEl, label) -> {setGreen,setRed,setGrey,destroy}`. Phase 16 uses exactly this signature (plugin.js:564–569) and calls `.setGreen/.setRed/.setGrey(tooltip)` + `.destroy()`. NO BREAKING CHANGES.
