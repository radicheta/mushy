### T1 — System hardening (claude-led, operator-watches)

Run on VPS via SSH:

```bash
# Update + upgrade
apt update && apt upgrade -y

# Install hardening tools
apt install -y ufw fail2ban unattended-upgrades wireguard wireguard-tools qrencode

# UFW: deny incoming default, allow SSH (22/tcp) + WG (51820/udp)
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp
ufw allow 51820/udp
ufw --force enable

# fail2ban: enable + start (default jail.d covers SSH)
systemctl enable --now fail2ban

# unattended-upgrades: enable + ensure security updates configured
dpkg-reconfigure -plow unattended-upgrades  # or seed /etc/apt/apt.conf.d/20auto-upgrades

# SSH hardening: key-only, no root password, no password auth
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#*PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
systemctl restart ssh
```

**Verify:**
- `ufw status verbose` → both rules present, default deny incoming
- `systemctl is-active fail2ban` → active
- New `ssh root@<vps-ip>` (with key) still works
- New `ssh -o PubkeyAuthentication=no root@<vps-ip>` should now FAIL

### T2 — WireGuard hub (claude-led)

```bash
# Enable IP forwarding (in case we want spoke-to-spoke later)
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-wg-forward.conf
sysctl -p /etc/sysctl.d/99-wg-forward.conf

# Generate hub keypair
cd /etc/wireguard
umask 077
wg genkey | tee hub.key | wg pubkey > hub.pub

# Initial wg-hub.conf (no peers yet)
cat > /etc/wireguard/wg-hub.conf <<EOF
[Interface]
Address = 10.66.0.1/24
ListenPort = 51820
PrivateKey = $(cat hub.key)
SaveConfig = false
EOF

systemctl enable --now wg-quick@wg-hub
wg show wg-hub
```

**Verify:** `wg show wg-hub` reports interface up, listening on 51820, no peers yet. `ip addr show wg-hub` shows 10.66.0.1/24.

### T6 — Add zoy as beta-tester peer (claude-led config gen, operator-led delivery)

zoy generates her own keypair (or we pre-gen and ship — operator decides; gen-on-her-end is the usual recommendation but slower). For tonight, claude pre-generates a peer config that includes a fresh keypair, ships it to operator, operator delivers via Signal to zoy.

zoy gets `10.66.0.20/32`. AllowedIPs on zoy's side is `10.66.0.0/24` (she can reach anyone on the hub). On the hub, AllowedIPs for zoy is `10.66.0.20/32` (she can ONLY appear from her assigned IP).

```bash
# On VPS as root
cd /etc/wireguard
wg genkey | tee zoy.key | wg pubkey > zoy.pub
cat <<EOF > /tmp/zoy-wg-mushy.conf
[Interface]
Address = 10.66.0.20/32
PrivateKey = $(cat zoy.key)

[Peer]
PublicKey = $(cat hub.pub)
Endpoint = <vps-ip>:51820
AllowedIPs = 10.66.0.0/24
PersistentKeepalive = 25
EOF
qrencode -t ansiutf8 < /tmp/zoy-wg-mushy.conf  # for phone scan if she uses WireGuard mobile

# Add zoy to hub
cat >> /etc/wireguard/wg-hub.conf <<EOF

[Peer]
# zoy (beta-tester #1)
PublicKey = $(cat zoy.pub)
AllowedIPs = 10.66.0.20/32
EOF
systemctl restart wg-quick@wg-hub
```

**Operator:** scp `/tmp/zoy-wg-mushy.conf` off the VPS, send to zoy via Signal (encrypted DM). Walk her through `wg-quick up` or WireGuard app import.

## Risk register

- **Breaking fc1's existing wg0** — D-12 hard rule. After T4, verify `ssh ubuntu@172.16.10.5` from elder-plops BEFORE moving on. If broken: stop, debug, do not proceed.
- **SSH lockout** — if `PasswordAuthentication no` lands before key works, you're locked out and need Hetzner console rescue. Mitigation: T1 verifies key auth BEFORE the sed flips password auth off.
- **UFW lockout** — if UFW enabled before SSH rule added, same problem. Mitigation: T1 adds rules BEFORE `ufw enable`.
- **Time pressure → typos in keys/configs** — at 3am, a missing `=` in a key string silently breaks things. Mitigation: I generate configs from captured pubkeys verbatim, not by re-typing.
- **zoy's WireGuard client compatibility** — phone vs laptop, app version. Mitigation: send both .conf and QR code.
