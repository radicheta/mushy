## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-02-01 | T (Tampering) | Duty topic injection | accept | ROS_DOMAIN_ID=69 isolation + Tailscale-only network reachability already gates the bus. Anyone on the tailnet can publish to humidifier_duty, same trust model as Phase 03/04 (target_humidity, humidifier Bool). No regression. |
| T-27-02-02 | D (Denial of service) | Stuck-high integrator drains tank | mitigate | Rolling 5-min cap (D-12, default 0.40) caps water consumption regardless of duty input. Hardcoded into fc_pwm_driver — controller cannot bypass. |
| T-27-02-03 | D (Denial of service) | Duty publisher silent → relay stuck-on | mitigate | Defensive OFF on `duty_topic_timeout_seconds` (default 5s). If fc_controller crashes mid-window with relay HIGH, fc_pwm_driver forces relay LOW within 5 ticks. Tested by `test_duty_silence_forces_off`. |
| T-27-02-04 | T (Tampering) | Out-of-range duty values | mitigate | `_duty_callback` clamps to [0.0, 1.0] before any windowing math runs. Tested by `test_clamps_negative_duty_to_zero` and `test_clamps_above_one_to_one`. |
| T-27-02-05 | I (Information disclosure) | GPIO state | accept | Bool topic content is public on the bus by design (operator monitors it). No PII. |

**Conclusion:** Plan 02 introduces no new external trust boundary. Defensive-OFF and rolling-cap are belt-and-suspenders against fc_controller misbehavior. ASVS L1: no high-severity threats; mitigations are baked into the windowing math.
