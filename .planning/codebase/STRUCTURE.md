## Directory Purposes

**src/chambers/fc-core:**
- Purpose: Core fruiting chamber environmental control system
- Contains: ROS2 package, sensor/control nodes, config, launch files, tests
- Key files: `fc_core/` module, `launch/fc.launch.py`, `config/fc_config.yaml`

**src/chambers/fc-core/fc_core:**
- Purpose: Python module containing executable nodes
- Contains: Four separate node implementations (sensors, controller, display, telemetry)
- Key files: Four main `.py` files + test subdirectory

**src/incubators/ic-core:**
- Purpose: Placeholder for future incubator subsystem
- Contains: Only Dockerfile stub
- Status: No active implementation

**src/life-support/ls-core:**
- Purpose: Placeholder for future life-support subsystem
- Contains: Only Dockerfile stub
- Status: No active implementation

**src/mission-control/bridge:**
- Purpose: Bridge layer connecting frontend to ROS backend
- Contains: Package setup, launch config, fake sensor utilities
- Status: Partially implemented (bridge structure present, main bridge logic not yet implemented)

**src/mission-control/frontend:**
- Purpose: Web-based monitoring interface
- Contains: Docker build for OpenMCT, custom plugin for fruiting chamber
- Key files: `plugins/fruiting-chamber/plugin.js` (telemetry and view logic)

**src/ros-core:**
- Purpose: ROS2 daemon container
- Contains: Dockerfile for standalone ros:jazzy-ros-core
- Status: Minimal; used as base for other services

**src/simulation:**
- Purpose: Gazebo simulation environment for testing without hardware
- Contains: Dockerfile, entrypoint, GUI configuration
- Status: Provides GPU-enabled simulation option

## Key File Locations

**Entry Points:**
- `src/chambers/fc-core/fc_core/fc_sensors.py`: Sensor data acquisition (executable)
- `src/chambers/fc-core/fc_core/fc_controller.py`: Control loop (executable)
- `src/chambers/fc-core/fc_core/fc_display.py`: Status display (executable)
- `src/chambers/fc-core/fc_core/fc_telemetry.py`: WebSocket telemetry (executable)

**Configuration:**
- `src/chambers/fc-core/config/fc_config.yaml`: All tunable parameters
- `src/chambers/fc-core/launch/fc.launch.py`: Orchestrates node startup

**Core Logic:**
- `src/chambers/fc-core/fc_core/fc_controller.py`: Temperature/humidity PID-like control
- `src/chambers/fc-core/fc_core/fc_sensors.py`: Hardware abstraction for sensor reads
- `src/mission-control/frontend/plugins/fruiting-chamber/plugin.js`: Frontend telemetry subscription

**Testing:**
- `src/chambers/fc-core/fc_core/test/test_controller.py`: Controller unit and integration tests

**Docker Orchestration:**
- `docker-compose.yml`: Service definitions (openmct, life_support)
- `Dockerfile`: Root container for OpenMCT
- `src/chambers/fc-core/Dockerfile`: fc_core service container
- `src/mission-control/frontend/Dockerfile`: OpenMCT builder
- `src/simulation/Dockerfile`: Gazebo simulator with GPU

## Naming Conventions

**Files:**
- Node modules: `fc_[component].py` (e.g., `fc_controller.py`, `fc_sensors.py`)
- Test files: `test_[component].py` (e.g., `test_controller.py`)
- Launch files: `[package].launch.py` (e.g., `fc.launch.py`)
- Config files: `[package]_config.yaml` (e.g., `fc_config.yaml`)
- Plugin files: Descriptive names (e.g., `plugin.js`, `plugin.css`)

**Directories:**
- ROS packages use lowercase with hyphens (e.g., `fc-core`)
- Python modules use lowercase with underscores (e.g., `fc_core`, `mission_control_bridge`)
- Config directories: `config/`
- Launch directories: `launch/`
- Plugin directories: `plugins/[feature-name]/`

**Classes:**
- Node classes: PascalCase with "Node" suffix (e.g., `FruitingChamberController`, `FruitingChamberSensors`)
- Exported functions: `main()` entry point for each executable node

**Topics/Messages:**
- Topics: kebab-case prefixed with domain (e.g., `fc/temperature`, `fc/humidity`)
- Message types: ROS standard types from sensor_msgs (Temperature, RelativeHumidity)

**Parameters:**
- YAML keys: snake_case (e.g., `simulation_mode`, `target_temp`, `fan_pwm_freq`)

## Where to Add New Code

**New Sensor Node:**
- Implementation: Create `src/chambers/fc-core/fc_core/fc_[sensor].py`
- Launch: Add Node entry to `src/chambers/fc-core/launch/fc.launch.py`
- Tests: Add `src/chambers/fc-core/fc_core/test/test_[sensor].py`
- Config: Add parameters to `src/chambers/fc-core/config/fc_config.yaml`

**New Controller Module (e.g., lighting subsystem):**
- Implementation: Add to `src/chambers/fc-core/fc_core/fc_controller.py` as method or separate node
- If separate node: Follow sensor pattern above
- Tests: Extend `test_controller.py` or create `test_[subsystem].py`

**New ROS Package (e.g., complete subsystem):**
- Package directory: `src/[category]/[system]-core/`
- Structure: Follow `fc-core` layout (fc_core module, launch/, config/, setup.py, package.xml)
- Entry: `setup.py` defines console_scripts for executables

**Frontend Extensions:**
- Plugin code: `src/mission-control/frontend/plugins/[feature-name]/`
- Files: `plugin.js` (logic), `plugin.css` (styling), `index.js` (entry)
- Integration: Loaded by OpenMCT when container starts

**Utilities/Helpers:**
- Shared helpers: Create in `src/[package]/[module]/` with clear module name
- No shared library folder; keep packages self-contained

## Special Directories

**build/:**
- Purpose: Colcon build artifacts
- Generated: Yes (created by `colcon build`)
- Committed: No (.gitignore)
- Contents: Intermediate build files per package

**install/:**
- Purpose: Final installed packages ready for deployment
- Generated: Yes (created by `colcon build`)
- Committed: No (.gitignore)
- Contents: Ready-to-run Python packages, launch files, configs

**log/:**
- Purpose: ROS2 log files (stderr, stdout from nodes)
- Generated: Yes (created by launch system)
- Committed: No (.gitignore)
- Contents: Node logs, timestamps, debug output

**docker-compose.override.yml:**
- Purpose: Local development overrides (ports, environment)
- Generated: No (created manually if needed)
- Committed: No (.gitignore)
- Use case: Override service ports or volumes for local testing
