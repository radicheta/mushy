## Bugs surfaced

### #1 (CRITICAL, FIXED) - Stale commit_failed drafts trapped every fresh capture

**File:** `fix(50): stale commit_failed drafts no longer trap fresh captures` (commit `370c6ed`).

`findActiveDraftsForSender` (Phase 50-04) included EVERY `commit_failed` draft regardless of age. Santi had 5 stale ack-debt drafts from May 13-21. When he sent a fresh capture, the parser greedily classified the text as EDIT (parser.parseReply default), the receive-loop saw `activeDrafts.length > 1`, fired numbered ask-back, and `continue`d -- skipping `insertCapture` entirely. Fresh captures vanished.

Hotfix: age out `commit_failed` drafts >6h in `findActiveDraftsForSender`. `awaiting_farmer` never ages out. EDIT-by-quote on older `commit_failed` still works via Phase 50 quote-resolution (bypasses this gate). Regression test added.

**Validation:** post-hotfix, Santi's "DT tubs 0519 1 and 2" + 2 follow-up texts all captured cleanly.

### #2 (HIGH, FIXED) - Operator-channel ping leaked to farmer surface (trinity-bleed)

**File:** `fix(38): trinity-skip operator-channel pings when operator==sender` (commit `6b4cbde`).

Phase 38 Plan-08's `sendBatchReviewSummary` (multi-draft paper-log scan) and `sendNeedsReviewPing` (ask-back cap hit) target `operatorRecipient` (env: `SIGNAL_RECIPIENT`). The radicheta/santi/farmer-1 trinity (per `[[user_santi_radicheta_farmer1_trinity]]`) means operator-recipient IS Santi's own Signal number. While Santi-as-farmer was in active conversation, he got an operator-debug ping addressed to "Don Santiago" containing his own phone number written back + opaque 10-char draft-id hex fragments + internal `clean/needs_review` mechanics.

Hotfix: skip operator-channel ping when `operatorRecipient === senderE164`. Other-farmer cases (Vikki, Selina) still ping Santi-as-operator normally. Regression tests added.

### #3 (MEDIUM, BACKLOG) - Phase 38 batch-mode routes 2-draft captures into needs_review queue

**File:** `.planning/todos/pending/2026-05-24-phase38-batch-mode-misroutes-small-multi-draft-captures.md`

`drafts.length > 1` automatically routes through Plan 08 batch-mode review queue, which auto-marks every draft `needs_review` with reason `batch_mode_low_conf` and suppresses the per-draft `confirm_prompt`. Conflates true paper-log scans (10+ rows, low confidence) with multi-event single messages (2-3 tubs, high confidence). Result: tonight's two well-formed DT drafts (per-field confidence 0.8-0.9) sit in limbo, never previewed to farmer, never committed.

Proposed fix: heuristic at routing seam -- `drafts.length > 5 OR min(per-draft confidence) < 0.7` -> review queue; else -> N normal `confirm_prompt`s through Phase 39. Eval fixture: tonight's `01KSCW771VB2FDWBPWNS4MEHAZ` capture preserved as named regression case.

### #4 (LOW, BACKLOG) - Photo-vs-paper-log classifier too eager

**File:** `.planning/todos/pending/2026-05-24-phase38-photo-vs-paper-log-classifier-too-eager.md`

Data quality recovered fine (`asset_ref=260519_DT_1`/`_2` correctly inferred from caption), but the `capture_kind` classification is wrong. Lower priority once #3 routing bug is fixed.

## Deeper design gap surfaced: observation-of-unknown-asset

Santi's framing during triage: **"if the farmer is recording an observation, the system replying 'that asset does not exist' would be comically wrong."** When a farmer reports an observation against asset X and X is missing from farmOS, the farmer just told us X exists in the physical world; the system's job is to reconcile, not to reject.

Today's `commit-observation.js:22-24` returns `observation_requires_target` (commit_failed) if `resolveQr` finds zero assets. This is correct for absurd inputs (typos, hallucinated IDs) but wrong for the "I haven't logged this block yet, observing it for the first time" case -- which is the production-normal case when a new batch enters the farm.

Backfill design captured separately at `.planning/todos/pending/2026-05-24-observation-of-unknown-asset-should-backfill-not-fail.md`. Likely a Phase 52+ deliverable; needs farmer-confirm UX for the auto-create (double-check the inferred ID against fuzzy-match neighbors before minting).

## Lessons

1. **Stale-state ageing is a routing concern, not just a UI concern.** Phase 50's ambiguity calc assumed `commit_failed` was "actively waiting for farmer action"; in practice it's a long-tail of operator-bound debt. Active-set queries need explicit time windows.
2. **Trinity-bleed is a real production concern, not an edge case.** The same human IS the operator + farmer-1 + project owner. Any operator-channel send needs to ask "what role is this person in right now?" before firing.
3. **Real-data UAT > curated eval, every time.** All four bugs were latent in hermetic-green code paths. Tonight's 90-min smoke surfaced more than 800 hermetic tests did, exactly as `[[feedback_real_data_before_ship_gate_pass]]` predicts.
4. **Observation-of-unknown-asset is the canonical reason FARMOS_INTEGRATION=0 is the right default today.** The bot can't fail-loudly to the farmer ("that asset doesn't exist") without losing trust; until the auto-backfill flow lands, write-through-to-farmOS prod is a regression risk, not a feature.
