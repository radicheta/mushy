## Process Findings (for future milestones)

From the first-pass audit that triggered this paperwork closure:

- **Verifier must check the live compose, not the file the plan edited.**
  Phase 07's verifier read `src/docker-compose.yml` and found everything
  passing. The actual live compose was `/docker-compose.yml` (created
  during the elder-plops migration), which was missing timescale and
  bridge env. Historical data silently broke for weeks as a result.
  Saved as memory `feedback_verify_runtime_compose.md`.

- **`docker-compose up -d` without `--build` is an invisible trap.** The
  Phase 07 Node.js bridge source was in the repo but the running image
  was still the pre-Phase-07 rosbridge image. The `up -d` command recreated
  the container from the stale cached tag without anyone noticing.

- **Phase SUMMARY.md `requirements-completed` frontmatter convention is
  not uniform across phases.** Some use the field, some don't. If the
  audit workflow relies on it for scoring, the SUMMARY template should
  enforce it.
