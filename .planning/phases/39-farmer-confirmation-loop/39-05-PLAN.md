<objective>
Integrate the EDIT loop: route a farmer's `EDIT <text>` reply back through the Phase 38 extractor with the correction supplied as additional context, persist the revised draft in place (same draft id, same source_capture_ids), and prepare an outbound `send_preview_resend` so the farmer sees the new preview in their next Signal message.

Two surfaces:
1. Phase 38's `extractor.js` gains one new optional parameter (`farmerCorrection`) that flows into the LLM prompt. This is a surgical add -- when null, behavior is byte-identical to the Plan 09 PASS attestation.
2. A new `src/agents/alerter/src/confirm/edit-handler.js` is the orchestrator the receive-loop calls when the parser returns `kind:'EDIT'`. It coordinates Plan 01's confirm-db helpers + the extractor + the preview renderer.

Important: this plan does NOT touch the receive-loop. Plan 06 owns wiring. This plan ships the EDIT *capability* + tests; Plan 06 ships the *invocation*.

LLM cost control: tests MUST use a mocked extractor. The real-data ship gate (Plan 07) is where one or two live LLM smokes happen, with per-call unique JSONL paths.
</objective>

<action>
Create `src/agents/alerter/src/confirm/edit-handler.js`. Top comment names Phase 39 + D-03 + D-03a.

Factory function `createEditHandler({ pool, extractor, confirmDb, previewBuilderConfirm, previewBuilderExtraction, stateMachineExtraction, config, logger = console })`:

- `pool`: pg pool.
- `extractor`: the Phase 38 extractor instance.
- `confirmDb`: the Plan 01 module (or its exports).
- `previewBuilderConfirm`: the Plan 04 confirm-flavored renderer (uses buildPreviewWithSuffix).
- `previewBuilderExtraction`: the Phase 38 preview-builder (used for the body; confirm renderer wraps it).
- `stateMachineExtraction`: Phase 38 state-machine module -- imports REQUIRED_FIELDS.
- `config`: from config.load(). Reads `config.maxEditTurns`, `config.extractionConfidenceThreshold`.

Returns `{ handleEdit }`:

`async handleEdit(draftRow, editText) -> Promise<{ok, reason?, newPreview?, sideEffect?}>`:

1. Pre-cap check: if `(draftRow.edit_turn_count || 0) >= config.maxEditTurns` -> return `{ok:true, sideEffect:'send_edit_cap_msg', reason:'edit_cap_exceeded'}`. The caller (Plan 06) will call `confirmDb.expireDraft(pool, draftRow.id, 'edit_cap_exceeded')` and send the message. (We don't call the state-machine in this branch because the cap decision is also encoded in the state-machine for clarity, but this short-circuit avoids burning an LLM call at the cap.)
2. Bump: `const bump = await confirmDb.bumpEditTurn(pool, draftRow.id);`. If `!bump.ok` -> log warn, return `{ok:false, reason:bump.reason}`.
3. Re-extract: `const result = await extractor.extract({ captures:[{captureId:'edit-' + draftRow.id, text:null, transcript:null, images:[], farmerCorrection: editText}], inFlightDraft: draftRow.draft_json, farmerCorrection: editText });` (also pass the field at the top level; the extractor reads `farmerCorrection` from the top-level call args, NOT from inside the capture item -- this matches the buildInitialUserContent signature change in task 1).
4. On `!result.ok`: log warn `[edit-handler] re-extract failed: ${result.reason}`. Append an event row via `confirmDb.appendEventViaPool(pool, draftRow.id, 'edit', {ok:false, reason:result.reason, editText:editText.slice(0,200)})`. Return `{ok:false, reason: result.reason}`. The draft stays at status='awaiting_farmer' (no status update issued).
5. On `result.ok`: pick `result.draft` (first/legacy single-event view -- this handler does NOT run in batch mode). Build the new preview via the confirm-flavored renderer:
   ```js
   const required = stateMachineExtraction.REQUIRED_FIELDS[result.draft.type] || [];
   const newPreview = previewBuilderConfirm.buildPreviewWithSuffix({
     draft: result.draft,
     perFieldConfidence: result.per_field_confidence || {},
     requiredFields: required,
     threshold: config.extractionConfidenceThreshold,
   });
   ```
6. Persist the revised draft: `const upd = await confirmDb.updateDraftAfterEdit(pool, draftRow.id, { draftJson: result.draft, perFieldConfidence: result.per_field_confidence || null, farmerFacingPreview: newPreview })`. On `!upd.ok` -> log warn, return `{ok:false, reason:upd.reason}`. On `upd.rowCount === 0`, the draft was no longer awaiting_farmer when the UPDATE landed (concurrent confirm/expire) -- log info, return `{ok:true, sideEffect:'noop', reason:'draft_no_longer_active'}`.
7. Append event: `await confirmDb.appendEventViaPool(pool, draftRow.id, 'edit', {ok:true, edit_turn: bump.edit_turn_count, editText:editText.slice(0,200)})`.
8. Return `{ok:true, sideEffect:'send_preview_resend', newPreview, nextEditTurnCount: bump.edit_turn_count}`. The caller (Plan 06) consumes `sideEffect` and dispatches outbound.

Wrap the whole thing in `try { ... } catch (e) { logger.warn('[edit-handler] error: ' + e.message); return {ok:false, reason:e.message}; }`. Never throws.

200-line ceiling. Pure JS, no framework.
</action>
