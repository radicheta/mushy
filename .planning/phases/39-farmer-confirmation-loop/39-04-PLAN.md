Build the pure-function state machine + farmer-text renderer for Phase 39. The state machine emits next-state + side-effect tags (no IO); the renderer turns those tags into the actual Signal-bound strings. Plan 06 will wire both into the receive loop and the watchdog.

This plan does NOT call the DB, the LLM, or signal.js. It DOES depend on Plan 01's `confirm-db.js` solely to import the audit-table event-name constants and the column-name conventions -- not to call any function.

Why split state-machine + renderer from the dispatcher? Same reason Phase 38 split state-machine.js from outbound.js: the FSM is the part that has to be exhaustively tested without IO, and the renderer is the part that has to be exhaustively style-locked against the project memory rules (no em-dashes, fmtNum).

<action>
Create `src/agents/alerter/src/confirm/state-machine.js`. Top-of-file comment naming Phase 39 + the D-decisions covered.

Exports:

- `CONFIRM_STATUS = Object.freeze({ AWAITING_FARMER:'awaiting_farmer', CONFIRMED:'confirmed', DISCARDED:'discarded', EXPIRED:'expired', NEEDS_REVIEW:'needs_review' })`
- `CONFIRM_EVENTS = Object.freeze({ FARMER_YES:'farmer_yes', FARMER_NO:'farmer_no', FARMER_EDIT:'farmer_edit', NUDGE_DUE:'nudge_due', EXPIRE_DUE:'expire_due', SUPERSEDED:'superseded' })`
- `transition(state, event)` -- pure function. `state = { status, edit_turn_count, nudge_sent_at }`. `event = { type: <one of CONFIRM_EVENTS>, maxEditTurns?: int, editText?: string }`.
- `isTerminal(status)` -- helper returning `true` for confirmed | discarded | expired | needs_review.

Return shape: `{ nextStatus, nextEditTurnCount, side_effects: string[], reason: string }`.

Transitions (each case below MUST be present):

1. `state.status !== 'awaiting_farmer'` AND event.type !== FARMER_YES on a CONFIRMED state (special-case below):
   - Return `{ nextStatus: state.status, nextEditTurnCount: state.edit_turn_count, side_effects:['noop'], reason:'inactive' }`.

2. event.type = FARMER_YES, state.status = 'awaiting_farmer':
   - `{ nextStatus:'confirmed', nextEditTurnCount: state.edit_turn_count, side_effects:['send_confirm_ack'], reason:'farmer_yes' }`

3. event.type = FARMER_YES, state.status = 'confirmed' (D-02 + D-02a soft re-affirm):
   - `{ nextStatus:'confirmed', nextEditTurnCount: state.edit_turn_count, side_effects:['send_confirm_idempotent_ack'], reason:'already_confirmed' }`

4. event.type = FARMER_NO, state.status = 'awaiting_farmer':
   - `{ nextStatus:'discarded', nextEditTurnCount: state.edit_turn_count, side_effects:['send_discard_ack'], reason:'farmer_no' }`

5. event.type = FARMER_EDIT, state.status = 'awaiting_farmer':
   - Let `cap = event.maxEditTurns ?? 3`.
   - If `state.edit_turn_count >= cap` -> `{ nextStatus:'needs_review', nextEditTurnCount: state.edit_turn_count, side_effects:['send_edit_cap_msg'], reason:'edit_cap_exceeded' }` (D-03a: the 4th EDIT triggers cap).
   - Else -> `{ nextStatus:'awaiting_farmer', nextEditTurnCount: state.edit_turn_count + 1, side_effects:['run_edit_reextraction'], reason:'edit_loop' }`. The dispatcher (Plan 06) consumes `run_edit_reextraction` and Plan 05's EDIT handler does the actual LLM call + preview re-render + outbound send.

6. event.type = NUDGE_DUE, state.status = 'awaiting_farmer', state.nudge_sent_at == null:
   - `{ nextStatus:'awaiting_farmer', nextEditTurnCount: state.edit_turn_count, side_effects:['send_nudge','mark_nudge_sent'], reason:'nudge' }`
7. event.type = NUDGE_DUE, state.nudge_sent_at != null:
   - `{ nextStatus: state.status, nextEditTurnCount: state.edit_turn_count, side_effects:['noop'], reason:'already_nudged' }`

8. event.type = EXPIRE_DUE, state.status = 'awaiting_farmer':
   - `{ nextStatus:'expired', nextEditTurnCount: state.edit_turn_count, side_effects:['send_expired_note'], reason:'timeout_expired' }`

9. event.type = SUPERSEDED (called when a new draft arrives and the watchdog/parser needs to close out an older awaiting_farmer row), state.status = 'awaiting_farmer':
   - `{ nextStatus:'expired', nextEditTurnCount: state.edit_turn_count, side_effects:['noop'], reason:'superseded_by_newer_draft' }`. No outbound send -- the supersession is silent (the new draft's preview is the new farmer-facing surface).

10. Default / unknown event.type -> noop branch.

The function MUST NOT touch `process.env`, log, or import anything that does IO.
</action>

The minutes value MUST go through `Math.round` first -- D-04a "round to whole minutes". sanitizeFarmerText.
- `buildExpiredNote()` -> `"Draft expired. Nothing was written. Send a fresh message if you still want to log this."` (D-04b). sanitizeFarmerText.
