# 999.33-04 — Chamber model in absolute moisture, with ambient ground truth

Design for **MUSHY-64** (ambient weather as offline ground truth) and
**MUSHY-60** (chamber model expressed in absolute moisture with temperature).
Both are children of MUSHY-52 / ROADMAP 999.33.

Written 2026-08-09. Supersedes nothing; extends `fc_core.sim.chamber_model`.

## Why

The current model is a first-order fit in **RH percentage points per hour**:

```
dRH/dt = applied_duty * fill_pts_per_hour - leak_pts_per_hour
```

RH points are not a conserved quantity. The same gram of water is a different
number of RH points at 3 C than at 10 C. FC-1 recorded 0.20 C to 28.4 C across
the 120-day window with 13-18 C daily swings, so a constant leak in RH points
cannot hold across it. Temperature is currently not in the model at all.

FC-1 sits in an uninsulated shipping container outdoors at
`-34.5165641, -55.0982273`. There is no building envelope between the chamber
and the weather, which is what makes outdoor weather a defensible ambient proxy.

## What the reformulation does and does not fix

**Does fix.** The temperature artifact, and the leak's physical basis. Solving
the current constants for an air-exchange rate gives an interpretable number:

| quantity | at 4.8 C, 90 % RH |
|---|---|
| 1 RH point | 0.386 g water in 5.76 m3 |
| leak 2.24 pts/h | 0.865 g/h |
| implied air exchange | ~2.6 m3/h, ~0.45 air changes/hour |

0.45 ACH is a plausible infiltration rate for a shipping container. The RH-points
constant yields no interpretable quantity at all. This is the main evidence that
the gradient formulation is the right shape.

**Does NOT fix.** The fill term stays an aggregate. The same arithmetic puts the
fitted fill at ~8.7 g/h against a misting head rated ~6 g/min (~360 g/h) -- the
~40x gap `chamber_model.py` already documents. An air-only moisture balance
reproduces that gap rather than resolving it, because the missing capacitance is
the wet substrate, and changing units does not conjure a second reservoir.

**Decision:** ship the single-state air balance (in scope for MUSHY-60), and file
the two-state air+substrate model as a follow-on. Do NOT let MUSHY-60 close
claiming full physical fidelity of the fill path.

## MUSHY-64 — ambient weather as offline ground truth

**Source.** Open-Meteo historical archive. Already the source named by ROADMAP
999.12; free, no API key, hourly resolution. Queried by coordinate.

**Window.** 2026-04-11 (first telemetry) onward. Non-nullness does NOT
establish that a value is final reanalysis: Open-Meteo backfills recent days
with preliminary ERA5T data and even returns future hours for the current day
(verified 2026-08-09: the archive returned non-null temperature through 23:00
UTC, hours that had not happened yet at fetch time). The earlier "no lag"
correction in this doc was unjustified on that evidence -- the original
~5-day-lag assumption was likely right about provenance, even if the specific
number was never confirmed. The fetch script now excludes today and anything
later than the moment of fetch, defaulting `--end` to yesterday. A sha256 of
the fixture is recorded in a `.meta.json` sidecar and checked by a test, so a
silent ERA5T-to-ERA5 revision on a later re-run fails loudly instead of
quietly changing the fit's input.

**Grid resolution.** The API snaps the request to a reanalysis grid cell at
`-34.48155, -55.088165`, elevation 253 m -- roughly 4 km from the container.
Ambient is therefore a nearby-cell estimate, not the air at the envelope. This
is the residual that MUSHY-67 exists to remove.

**Variables.** `temperature_2m`, `relative_humidity_2m`, `precipitation`.
Precipitation is not used by the model; it is carried because the farmer's
2026-04-12 request was explicitly to explain wet days.

**Two outputs, both required.**

1. **Committed fixture** -- hourly CSV at
   `src/chambers/fc-core/fc_core/sim/data/ambient_-34.52_-55.10.csv`, columns
   `time_utc,temp_c,rh_pct,precip_mm`. Mandatory, not a convenience: the test
   container runs `--network none`, so tests can never fetch. This is the
   artifact the sim depends on, and it ships inside the package so the
   container's read-only `/src` mount reaches it.
2. **Timescale `weather` table** -- same data loaded alongside the `fc.*`
   topics, following the shape ROADMAP 999.12 specifies, so weather is
   queryable next to chamber data for ad-hoc analysis. Columns
   `(time timestamptz, topic text, value double precision)` mirroring
   `telemetry`, with topics `weather.temperature`, `weather.humidity`,
   `weather.precipitation`, and a `(topic, time)` unique constraint so re-runs
   upsert rather than duplicate.

Script lives at `scripts/fetch-ambient-weather.py`.

**Fetch script.** One-shot, in-tree, idempotent, re-runnable to extend the
window. Not a daemon. Not scheduled.

**Explicitly out of scope** (from the ticket, retained): weather as a runtime
input to the controller. A stale or failed fetch would silently corrupt the
control path, and the chamber has a documented history of connectivity
problems. Weather is ground truth for fitting and validation only.

## MUSHY-60 — the model

**State variable.** Absolute moisture in the chamber air, `m` grams, over the
5.76 m3 interior.

**Psychrometrics.** Mirror `src/mission-control/bridge/src/fc_derived.js`
exactly -- Tetens saturation vapour pressure and `AH = (Mw/R) * e / T_K` with
`Mw/R = 2.1668`. Using the same formulation is what makes fitted values
comparable to the recorded `fc.water_vapor` series. A parity test pins this.

```
svp(T)   = 0.6108 * exp(17.27*T / (T + 237.3))        [kPa]
AH(T,RH) = 2.1668 * (svp(T) * 1000 * RH_frac) / T_K   [g/m3]
RH_frac  = AH * T_K / (2.1668 * svp(T) * 1000)        [inverse]
```

**Balance.**

```
V * dAH_in/dt = F * u(t) - Q * (AH_in - AH_out)
```

| symbol | meaning | units |
|---|---|---|
| `V` | chamber interior volume, 5.76 | m3 |
| `AH_in` | chamber absolute humidity | g/m3 |
| `AH_out` | ambient absolute humidity, from the MUSHY-64 fixture | g/m3 |
| `F` | effective fill rate (aggregate -- see limitation) | g/h |
| `Q` | air-exchange conductance | m3/h |
| `u` | delivered duty, 0..1 | -- |

Dead time and first-order mixing carry over from the current model unchanged
(transport-delay queue plus `tau_s`); this design changes the moisture balance,
not the lag structure.

**Parameters.** `leak_pts_per_hour` and `fill_pts_per_hour` are replaced by `Q`
and `F`. Both are fitted once against the recorded window and are expected to be
season-independent, which is the point.

**Fitting method.** Two-parameter least-squares on `dAH_in/dt` residuals, over
1-minute-resampled telemetry joined to hourly ambient (ambient linearly
interpolated to the telemetry grid). `Q` is identified from quiet intervals
where `u == 0` over a window longer than the dead time, so the fill term drops
out and the leak is observed alone; `F` is then identified from active
intervals holding `Q` fixed. Fitting the two sequentially rather than jointly
avoids the degeneracy where a larger `F` and a larger `Q` trade off against each
other. Season-independence is a claim to be TESTED, not assumed: fit on the
April-June half, validate on July-August, and report both parameter sets. If
they disagree materially, say so rather than refitting to hide it.

**`equilibrium_duty` stops being a constant** and becomes a function of
conditions:

```
u* = Q * (AH_in - AH_out) / F
```

This is what dissolves the seasonal caveat recorded on MUSHY-57: the humidifier
bias no longer rests on a duty measured once at 4.8 C in winter.

## Testing

**New.**
- Psychrometric unit tests: `svp`, `AH`, and `AH -> RH` round-trip.
- Parity test against `fc_derived.js` reference values, so the Python and the
  recorded telemetry cannot drift.
- Air-exchange plausibility: fitted `Q` must land in a sane ACH range for a
  container, not an arbitrary curve-fit value.
- Fit quality against the recorded window using real ambient.

**Regression -- must stay green.**
- The existing fidelity gate. The new model must still reproduce the 2026-08-08
  limit cycle, or it is not modelling the same chamber.
- All MUSHY-57 duty-bias behaviour.

**Migration note.** The MUSHY-57 high-ambient test constructs its scenario as
`ChamberParams(leak_pts_per_hour=0.0)`. That parameter ceases to exist. The test
must be re-expressed as the physically equivalent zero-gradient condition,
`AH_out == AH_in` -- which is a strictly better statement of the same intent,
since "high ambient humidity" is now directly representable instead of being
faked by deleting the leak.

## Limitations, recorded deliberately

1. **Fill remains an aggregate** (~40x below the misting head's nameplate). The
   substrate is the unmodelled reservoir. Follow-on ticket: two-state
   air+substrate model.
2. **Solar gain is unmodelled.** On hot sunny days an uninsulated steel
   container runs hotter inside than outdoors. The fitting window
   (April-August) is austral autumn/winter, so solar contamination of the fit is
   small -- but this means the model will still extrapolate poorly into summer,
   for a physical reason rather than a curve-fitting one. MUSHY-60 must not
   close claiming season independence. Follow-on ticket: solar gain term,
   revisit in summer.
3. **Ambient is measured at a weather station, not at the container.** MUSHY-67
   (ambient measured at the chamber) remains the eventual upgrade; this design
   keeps ambient behind an interface so a real sensor can replace the fixture
   with no model change.
4. **`fc.water_vapor` is derived, not measured** -- it is a pure function of
   `fc.temperature` and `fc.humidity` computed bridge-side. It carries no
   information beyond those two series. Used here as the convenient state
   variable, not as independent evidence.
5. **The gradient is small and noisy, and the gate is weak.**

   | month | hours | mean gap g/m3 | sd | % hours negative | % chamber RH pegged >=99.99 |
   |---|---|---|---|---|---|
   | Apr | 435 | 1.30 | 1.84 | 22.8 | 37.5 |
   | May | 719 | 1.52 | 1.38 | 9.7 | 0.0 |
   | Jun | 720 | 1.27 | 1.14 | 10.3 | 0.0 |
   | Jul | 729 | 0.65 | 1.35 | 40.3 | 0.0 |
   | Aug | 203 | 0.30 | 1.25 | 55.2 | 0.0 |

   The standard deviation is 2-6x the monthly mean throughout, and in August
   the gradient points INWARD for the majority of hours. The uninsulated
   container tracks ambient temperature almost exactly (monthly chamber/ambient
   means 15.7/16.1, 11.1/10.5, 9.5/8.8, 10.7/10.5, 10.7/11.0), so the gradient
   reduces to roughly (RH_in ~94% - RH_out ~86%) at near-equal temperature.
   Since `Q = flux / gradient`, `Q` is WEAKLY IDENTIFIED in exactly the
   July-August half that this design designates as the validation half. If
   validation fails there, the honest reading may be "the gradient was
   unresolvable", NOT "the parameters are season-dependent".
6. **Chamber RH saturates at 100%.** Over the fitted window `fc.humidity`
   ranges 61.85-100.0 (mean 94.3). Readings pinned at exactly 100.0 are sensor
   saturation, not measurement -- and this is 37.5% of April's chamber hours,
   the month with the largest apparent gradient. All of that truncation is
   downward, so April's true gap is LARGER than measured and the seasonal
   decline is STEEPER than the table above shows.

   **RULING (farmer, 2026-08-09): treat 100.0 as a saturated membrane, and
   EXCLUDE those samples from the fit.** Not clamped -- clamping would take a
   ceiling for a measurement. Exclusion matters more for the derivative than
   for the level: a pinned sensor reports `dAH_in/dt == 0` while moisture is
   genuinely changing, so a saturated stretch reads as "no net flux" and would
   teach the fit that the chamber does not leak during its wettest hours.
   Consequence to state when reporting `Q`: it is the air-exchange conductance
   **in the unsaturated regime**, not of the chamber unconditionally. That is
   the right domain for a loop that operates in-band near 90 % RH, but it must
   be labelled, not quietly generalised.
7. **`fc.humidity` silently mixes two sensors.** `fc1/humidity` is a failover
   slot: `fc_sensors.py:103-105` takes SHT30 per sample and falls back to
   SCD41 when SHT30 does not read, recording which one it used in the ROS
   message's `header.frame_id`. The bridge drops that -- `insertTelemetry`
   writes into `telemetry(time, topic, value)`, which has no source column --
   so the stored series cannot be attributed to a sensor, irrecoverably for
   history.

   This is load-bearing for a derivative-based fit. Over the window
   `fc.humidity` averages 93.4 % against `fc.humidity_2`'s 98.0 %
   (`fc.humidity_2` is ALWAYS SCD41, `fc_sensors.py:138`), so the two sensors
   disagree by ~4.6 points and every failover injects a step discontinuity.
   A step reads as an enormous spurious `dAH_in/dt` spike -- a worse artifact
   than the 100 % pinning, because it is transient and lands exactly where the
   leak signal lives.

   Mitigation available without re-architecture: `fc.humidity_2` is a
   provenance-clean single-sensor series and can serve as a cross-check. Where
   the two diverge by a step, a failover has occurred. Fix for future data:
   MUSHY-71. **Take the historical data as-is with a grain of salt** (farmer,
   2026-08-09) -- do not attempt retroactive attribution.
