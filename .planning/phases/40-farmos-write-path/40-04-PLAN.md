<action>
Create `src/agents/alerter/src/farmos/commits/commit-router.js`. Exports `commit(client, draft, ctx)` where:
- draft = the signal_draft row (id, log_type, draft_json, source_capture_ids, ...)
- ctx = `{commitDb, capturePathsFor: (captureIds[]) => Promise<string[]>, logger, clock}`

Logic:
```
if (!draft.log_type || !LOG_TYPES.includes(draft.log_type)):
  return {ok:false, reason:'unsupported_log_type', log_type: draft.log_type}

const t0 = clock.now()
const dispatch = { seeding: commitSeeding, activity: commitActivity, input: commitInput,
                   observation: commitObservation, harvest: commitHarvest }[draft.log_type]

const result = await dispatch(client, draft, ctx)
return { ok: result.ok,
         asset_ids: result.asset_ids || [],
         log_ids:   result.log_ids   || [],
         file_ids:  result.file_ids  || [],
         http_status: result.http_status,
         latency_ms: clock.now() - t0,
         reason: result.reason }
```

Wraps everything in try/catch:
- UnsupportedLogTypeError → `{ok:false, reason:'unsupported_log_type'}`
- Any other thrown error → `{ok:false, reason: e.message}`

No retries here -- retries happen at the watchdog level (Plan 05). One call to commit() = one attempt.
</action>
<acceptance_criteria>
- Unsupported log_type returns {ok:false, reason:'unsupported_log_type'} with NO fetch issued
- Successful dispatch returns aggregated result envelope with latency_ms populated
- Thrown error from inner module surfaces as ok:false (not propagated)
</acceptance_criteria>
</task>

<action>
Create `src/agents/alerter/src/farmos/commits/commit-seeding.js`. Signature `commitSeeding(client, draft, ctx)`.

draft.draft_json carries (per Phase 38 zod schema):
- batch_name (BATCH-*)
- block_name (YYMMDD_SPECIES_SEQ)
- species_code (short code, e.g. DT)
- timestamp (unix seconds)
- notes (farmer text)
- qr_codes[] (Phase 38 captured)

Flow:
1. **Batch resolve-or-create:**
   - `const batchResult = await assets.resolveOrCreateAsset(client, {name: draft.draft_json.batch_name, draftId: draft.id});`
   - On failure return ok:false with reason.
2. **Species lookup:** `const sp = await getSpeciesUuid(client, draft.draft_json.species_code);` -- fail fast if not found.
3. **QR Path detection:** for each qr_code in draft.draft_json.qr_codes:
   - `const r = await qr.resolveQr(client, qr_code);`
   - If r.found: this is Path B for that QR; the existing assetId becomes the block_id (no new block creation). Verify only one Path-B QR is allowed; if multiple, fail with reason='ambiguous_qr_seeding'.
   - If !r.found: Path A; collect for new-block creation.
4. **Block create (Path A):**
   - `const blockResult = await assets.createFungiAsset(client, { name: draft.draft_json.block_name, parentIds:[batchResult.assetId], speciesUuid: sp.uuid, qrCodes: pathAQrCodes, draftId: draft.id });`
5. **Seeding log:**
   - `const logResult = await logs.createLog(client, 'seeding', { name: 'Inoc ' + draft.draft_json.block_name, timestamp: draft.draft_json.timestamp, assetIds: [batchResult.assetId, blockResult.assetId], notes: draft.draft_json.notes || '', draftId: draft.id });`
6. Aggregate result.

Return `{ok:true, asset_ids:[batchId, blockId], log_ids:[seedingLogId], file_ids:[], http_status:201}`.
</action>
<acceptance_criteria>
- Existing-BATCH-* path issues NO POST for the batch
- New-BATCH-* path issues exactly one batch POST + one block POST + one seeding log POST
- Path-B QR (existing block) skips block creation
- species_not_found short-circuits BEFORE block creation
- Output envelope satisfies the router contract
</acceptance_criteria>
</task>

5. Result aggregates all created asset ids + the harvest log id.

</action>
