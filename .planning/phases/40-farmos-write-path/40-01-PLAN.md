<task id="2">
<title>Lifecycle functions: lock, mark, requeue, release-stale, getCached</title>
<read_first>
- src/agents/alerter/src/confirm/confirm-db.js -- markNudgeSent / expireDraft / confirmDraft patterns
- .planning/phases/40-farmos-write-path/40-RESEARCH.md section 6, 7, 9

<action>
Implement the following exported functions in `commit-db.js`. All never-throw; return `{ok, ...}` shape mirroring confirm-db.js.

1. `findConfirmedCandidates(pool, batchCap)` -- `SELECT * FROM signal_draft WHERE status='confirmed' ORDER BY confirmed_at ASC LIMIT $1`. Returns rows array.

2. `acquireCommitLock(pool, draftId)` -- atomic transition:
```sql
UPDATE signal_draft
   SET status = 'committing',
       committed_at_attempt = now(),
       commit_attempt_count = commit_attempt_count + 1
 WHERE id = $1 AND status = 'confirmed'
RETURNING *;
```
Returns `{ok: true, rowCount, row}` (row is null on rowCount=0 race-loss).

3. `markCommitted(pool, draftId, farmosResponse)` -- final terminal transition:
```sql
UPDATE signal_draft
   SET status = 'committed',
       farmos_response = $2,
       committed_at = now()
 WHERE id = $1 AND status = 'committing';
```
`farmosResponse` is a JS object: `{asset_ids[], log_ids[], file_ids[], http_status, latency_ms}`. JSON-encode via parameter binding.

4. `markFailed(pool, draftId, reason)` -- terminal failure:
```sql
UPDATE signal_draft
   SET status = 'commit_failed',
       commit_failed_reason = $2,
       committed_at = now()
 WHERE id = $1 AND status = 'committing';
```

5. `requeueForRetry(pool, draftId)` -- transient failure recovery:
```sql
UPDATE signal_draft
   SET status = 'confirmed',
       committed_at_attempt = NULL
 WHERE id = $1 AND status = 'committing';
```
(Backoff sleep happens in watchdog, not here.)

6. `releaseStaleLocks(pool, staleMin)` -- crash recovery:
```sql
UPDATE signal_draft
   SET status = 'confirmed',
       committed_at_attempt = NULL
 WHERE status = 'committing'
   AND committed_at_attempt < now() - ($1 || ' minutes')::interval
RETURNING id;
```

7. `getCachedResponse(pool, draftId)` -- idempotency probe (D-02a):
```sql
SELECT status, farmos_response, commit_failed_reason
  FROM signal_draft WHERE id = $1;
```
Returns `{ok:true, status, farmos_response, commit_failed_reason}` or `{ok:false, reason}`.

8. `getAttemptCount(pool, draftId)` -- simple read for the retry-budget decision in the watchdog.

All wrapped in try/catch returning `{ok:false, reason:e.message}`. No console.log.
</action>
<acceptance_criteria>
- 7 functions exported (initDb already covered in task 1; total 8 with initDb)
- acquireCommitLock under concurrent contention only wins once (asserted in task 4 test)
- markCommitted SQL has the `WHERE status='committing'` guard (assertable by grep)
- releaseStaleLocks RETURNS the released ids (for audit logging in watchdog)
- File total <= 260 lines
</acceptance_criteria>
