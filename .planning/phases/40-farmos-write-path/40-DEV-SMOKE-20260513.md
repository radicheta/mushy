## Bugs surfaced

### 1. `fungi_type` missing from alerter asset-create payload

**File:** `src/agents/alerter/src/farmos/assets.js:47-89` (`createFungiAsset`)

**Symptom:** First 422 from `POST /api/asset/fungi`:

```json
{"errors":[{"detail":"fungi_type: This value should not be null.","source":{"pointer":"/data/attributes/fungi_type"}}]}
```

**Fix shape:** `fungi_type` is a required field on the `asset--fungi`
bundle. Two sub-bugs:

1a. `createFungiAsset` doesn't set `fungi_type` at all -- needs a way to
plumb it through (`batch` for `resolveOrCreateAsset`, `block` for normal
create, plus the harvest path needs `batch` again for the harvest batch
and `bag` for bag creates).

1b. `fungi_type` is a **relationship** to `taxonomy_term--fungi_type`,
not an attribute. JSON:API contract:

```json
{
  "data": {
    "type": "asset--fungi",
    "attributes": { "name": "...", "status": "active" },
    "relationships": {
      "fungi_type": {
        "data": [ { "type": "taxonomy_term--fungi_type", "id": "<uuid>" } ]
      }
    }
  }
}
```

Same pattern as the existing `species` relationship code in `assets.js:64-66`.

### 2. dev-farmOS taxonomy is underseeded

Probed `/api/taxonomy_term/<tax>` on dev-farmOS to confirm Phase 40
expectations against actual instance state:

| Taxonomy | State | Phase 40 requirement |
|----------|-------|----------------------|
| `species` | **404 -- bundle does not exist** | Required for all seeding/harvest commits (species lookup in `species-cache.js`) |
| `fungi_type` | exists; 1 term: "SHI" | Should hold `batch`, `block`, `bag`, possibly `log`/`fruiting`/`spawn` -- currently has the species code "SHI" misplaced here |
| `substrate_type` | exists; 1 term: "Sawdust" | Used by seeding when substrate is set; needs full vocab |
| `log_category` | exists; empty | Used for B7 log-type categorization |

Asset bundle `asset--fungi` exists; types accepted: animal, equipment,
**fungi**, land, plant, structure, water.

`asset_link` module is **absent** (probe verdict; confirms 40-CONTEXT
D-04a fallback path is the live path on dev).

### 3. `species_lookup_failed` would never get triggered

`species-cache.js:33-35` returns `species_not_found` if the GET to
`/api/taxonomy_term/species?filter[name][value]=...` returns 0 rows. But
on dev-farmOS that GET returns **404 from routing** (bundle doesn't
exist) which the client treats as `http_404` not `species_not_found`.
Confusion class: misleading error code.

(In this smoke run, the 422 from asset-create fired BEFORE the species
lookup chain, so this path didn't actually run. Logged for completeness.)
