1. **Skip gate:** `const RUN = process.env.FARMOS_INTEGRATION === '1'; const d = RUN ? describe : describe.skip;`

2. **beforeAll:**
   - Connect to a real pg instance (test DB; honor TIMESCALE_URL or DATABASE_URL env)
   - Run `commitDb.initDb(pool)` + `confirmDb.initDb(pool)` + `extractionDb.initDb(pool)` to ensure schema is current
   - Build a real farmosClient against `${FARMOS_URL:-http://10.68.155.50:18080}` using FARMOS_USERNAME / FARMOS_PASSWORD

   - Pre-stage a fixed attachment file at a temp path for observation-photo.json to reference

3. **Per-scenario it-block** (8 total -- 7 curated + 1 prod):
   - Load fixture JSON
   - INSERT into signal_draft
   - Call `commitWatchdog.tickOnce()` once (deterministic; no setInterval)
   - Re-read signal_draft row
   - **Alerter-side assertions:**
     - status === 'committed' (or 'commit_failed' for unsupported-logtype)
     - farmos_response populated with asset_ids / log_ids / file_ids
     - signal_draft_event rows include commit_attempt and commit_success (or commit_failed)
   - **FarmOS-side assertions** (skip for unsupported-logtype + idempotency-replay):
     - For each asset_id: GET /api/asset/fungi/<id> returns 200 with expected name
     - For the log_id: GET /api/log/<type>/<id> returns 200 with the expected relationships
     - For observation: file_ids exist in /api/file/file/<id>
   - **Idempotency-replay extras:** before INSERTing the fixture, run the pipeline once (any of the prior scenarios); then INSERT the replay fixture (same draft.id); intercept fetch to count POST calls during the second tickOnce; assert POST count is 0.

4. **afterAll:** best-effort cleanup of created farmOS entities (DELETE via JSON:API) so re-runs are idempotent. Cleanup failure is logged but does not fail the suite (dev-farmOS is fine to grow).

5. The prod-fixture scenario gets its own it-block flagged `it('SHIP GATE: real-prod fixture commits end-to-end', ...)` with a comment naming the feedback memory.
