<task id="2">
<title>Request wrappers + retry + timeout + 401 reauth</title>
<read_first>
- .planning/phases/40-farmos-write-path/40-RESEARCH.md section 1, 7
- .planning/phases/40-farmos-write-path/40-CONTEXT.md D-07a

<action>
Implement `_request(method, path, body, opts)` (private) and the public verbs:
- `get(path, opts)`        -- method='GET', no body
- `post(path, body, opts)` -- method='POST', JSON body, Content-Type vnd.api+json
- `patch(path, body, opts)`-- method='PATCH', JSON body, Content-Type vnd.api+json
- `postBinary(path, bytes, opts)` -- method='POST', body=bytes, Content-Type application/octet-stream + Content-Disposition (caller-supplied via opts.filename)

`_request` behavior:
1. Lazy-auth on first call: if `_session.cookie == null`, await `_authenticate()`.
2. Build headers:
   - `Cookie: <session cookie>`
   - `X-CSRF-Token: <csrf>` (for write verbs only -- GET HEAD do not require but include defensively)
   - `Accept: application/vnd.api+json`
   - `Content-Type:` per verb (skip for GET)
3. AbortController with `opts.timeoutMs || timeoutMs`.
4. Try the fetch.
5. **Retry loop:**
   - On TypeError/AbortError/socket-level error: classify as transient; sleep backoffMs[attempt] and retry until `attempt >= retryMax`.
   - On 5xx response: transient; retry per backoff.
   - On 401/403: single re-auth attempt then retry the original call once; if still 401/403 surface the error as terminal.
   - On 4xx (other): terminal -- return the response (let caller read body and surface the failure).
   - On 2xx: success -- parse JSON if Content-Type matches vnd.api+json, else return raw text + status.
6. Return shape: `{ok, status, headers, body, latencyMs}`. `ok = status >= 200 && status < 300`.

`postBinary` uses Content-Type `application/octet-stream` and a 30s default timeout (override via opts.timeoutMs). Used by the file upload module (Plan 04).

Sleep helper uses `clock` injection so tests can fast-forward (`clock.sleep = (ms) => Promise.resolve()` in tests).
</action>
<acceptance_criteria>
- Successful 201 returns `{ok:true, status:201, body, latencyMs}`
- A single 500 followed by 200 succeeds with attempt=2 (asserted in unit test)
- 3 consecutive 500s exhaust retries; returns `{ok:false, status:500, ...}` without throwing
- 401 triggers exactly one re-auth + retry; second 401 returns `{ok:false, status:401}`
- 4xx (e.g. 422) returns `{ok:false}` without any retry (assert via fetch-call counter)
- All paths populate `latencyMs`
- File <= 280 lines
</acceptance_criteria>
