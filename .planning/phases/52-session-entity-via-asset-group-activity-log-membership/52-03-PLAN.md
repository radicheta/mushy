Handler signature unchanged: `commitSeedingSession(client, draft, ctx)` returns the same `{ok, asset_ids, log_ids, file_ids, http_status, reason?, farmos_response?}` shape used by the commit-router.

Two new categories of entities to surface in the return:
- `asset_ids` now includes the session group asset id (when newly created — `outcome==='created'`, not `'reused'`)
- `log_ids` now includes the membership activity log id at index 0 (membership log first, then N seeding logs)

Per 52-CONTEXT.md decisions:
- Session asset name: `inoc &lt;YYYY-MM-DD&gt;`, with `#2`...`#9` suffix on same-day collision
- Session asset notes: provenance trailer + draft id (mirror existing trailer pattern)
- Session asset has NO QR, NO fungi_type, NO parent[] — pure group asset
- Children: `parent=[sourceBlock]` ONLY — DO NOT add a secondary edge to the session group
- Membership log shape: name = `inoc &lt;YYYY-MM-DD&gt; (N bags)`, timestamp = same day-grain epoch as seeding logs

Collision logic: a tight loop that tries `inoc YYYY-MM-DD`, then `#2`, `#3`, ..., `#9` against `findGroupAssetByName`. Pick the FIRST name that either (a) misses → call upsertGroupAsset to create it; or (b) hits AN ASSET CREATED BY THIS DRAFT (notes trailer matches `mushy:draft:&lt;draftId&gt;`) → reuse. Otherwise advance to the next `#N`. If all 9 candidates are exhausted and none match the current draft, return `{ok:false, reason:'session_name_collision_exhausted'}`. This is the same `_resolveSessionName` logic Phase 48 originally locked.
