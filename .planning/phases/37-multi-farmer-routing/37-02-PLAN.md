       ```javascript
       function parseFarmerMap(raw) {
         const m = new Map();
         for (const entry of String(raw).split(',').map((s) => s.trim()).filter(Boolean)) {
           const idx = entry.indexOf(':');
           if (idx <= 0) continue;
           const phone = entry.slice(0, idx).trim();
           const slug = entry.slice(idx + 1).trim();
           if (phone && slug) m.set(phone, slug);
         }
         return m;
       }
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env vars → signal.js constructor | `SIGNAL_GROUP_ID` flows from operator-controlled `.env` into the default send target; misconfiguration could leak farm data to wrong group |
| env vars → config.signalFarmerMap | `SIGNAL_FARMER_MAP` controls farmOS person attribution; a typo could mis-attribute messages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-02-01 | Spoofing | signal.js defaultTarget | mitigate | Construction throws if neither defaultTarget nor recipient is set — prevents silent defaulting to `undefined` recipients (which signal-cli would 400 but log noisily) |
| T-37-02-02 | Tampering | parseFarmerMap on malformed env | mitigate | Defensive parsing: drops entries without exactly one `:`, with empty phone, or with empty slug; never throws; logs nothing (boot-time) — operator notices via missing farmer_map size in startup log (added in Plan 04 wire-up) |
| T-37-02-03 | Information disclosure | group recipient construction | mitigate | `group.` prefix concatenated server-side in signal.js means env value cannot accidentally route to a phone (string + object branch are distinct types — TypeScript-like discriminated union via `typeof`) |
| T-37-02-04 | Denial of service | schema migration on hot restart | accept | `ADD COLUMN IF NOT EXISTS text` on a small non-hypertable is sub-millisecond NULL-column add (RESEARCH Risk #7); no rewrite |
| T-37-02-05 | Elevation of privilege | new env vars from operator-controlled .env | accept | Same trust model as existing SIGNAL_* env vars; ASVS L1 |
</threat_model>
