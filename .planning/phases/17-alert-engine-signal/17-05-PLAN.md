    On elder-plops (as the operator, with farm network access):

    1. **Deploy signal-cli only (not alerter yet):**
       ```bash
       cd /opt/mushy   # or wherever elder-plops has the repo
       docker compose up -d --build signal-cli
       ```
       Temporarily add `ports: ["127.0.0.1:8085:8080"]` to the `signal-cli` service in override, run `docker compose up -d signal-cli`. **REMOVE this port mapping after registration succeeds** (D-13: internal-only).

       ```bash
       curl -sf http://localhost:8085/v1/about
       # Expect: JSON about response
       ```

    3. **Get the captcha token:**
       Open `https://signalcaptchas.org/registration/generate.html` in a browser. Solve the challenge. Right-click the "Open Signal" link that appears and Copy Link. It starts with `signalcaptcha://`.

    4. **Register:**
       ```bash
       curl -X POST 'http://localhost:8085/v1/register/+1XXXXXXXXXX' \
         -H 'Content-Type: application/json' \
         -d '{"captcha":"signalcaptcha://PASTE_HERE","use_voice":false}'
       # Expect: 201 or similar success
       ```
       Replace `+1XXXXXXXXXX` with the real 4G-SIM number.

    5. **Check the 4G router's SMS inbox** (or forwarding destination) for the 6-digit verification code. This is the step that can ONLY be done by a human. If SMS does not arrive within ~5 min, add `"use_voice":true` to step 4 and retry — the SIM will receive a voice call instead.

    6. **Verify:**
       ```bash
       curl -X POST 'http://localhost:8085/v1/register/+1XXXXXXXXXX/verify/NNNNNN'
       # Expect: 201
       ```

    7. **Confirm registration:**
       ```bash
       curl http://localhost:8085/v1/accounts
       # Expect: ["+1XXXXXXXXXX"]
       ```

    8. **Test send to self:**
       ```bash
       curl -X POST 'http://localhost:8085/v2/send' \
         -H 'Content-Type: application/json' \
         -d '{"message":"Mushy alerter registration test","number":"+1XXXXXXXXXX","recipients":["+1XXXXXXXXXX"]}'
       ```
       Farmer confirms message arrived on their phone.

    9. **Remove the temporary port mapping** from docker-compose.override.yml, rebuild: `docker compose up -d signal-cli`. Confirm `curl http://localhost:8085/v1/accounts` now fails (port no longer published — per D-13).

    10. **Edit `.env` on elder-plops** with real SIGNAL_SENDER and SIGNAL_RECIPIENT values (NOT `.env.example` — that stays as a template).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → elder-plops docker daemon | Trusted operator path — git push + docker compose |
| signal-cli ↔ Signal servers (internet) | External; E2E handled by Signal protocol; our container holds the account key in `signal-cli-data` volume |
| 4G SIM inbound SMS → operator (registration) | Pre-phase gate; operator reads code once |
| farmer phone ↔ signal-cli (via Signal network) | E2E encrypted by Signal; we don't see the transport |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Spoofing | signal-cli-data volume containing account keys | mitigate | Named Docker volume (not host bind) keeps keys inside Docker's managed storage; D-13 internal-only network; volume-permissions default to Docker daemon (root); encrypted-at-rest is OS-filesystem-dependent — documented as deferred in CONTEXT.md |
| T-17-03 | Information Disclosure | elder-plops `.env` contains SIGNAL_SENDER | mitigate | `.env` is git-ignored (existing convention); `.env.example` uses `+1XXXXXXXXXX` placeholder only; alerter boot log and runtime logs use `maskNumber` |
| T-17-04 | Elevation of Privilege | signal-cli container in internal-only network | mitigate | No `ports:` key on signal-cli service; alerter reaches it only via compose service-name DNS; attacker needs host root to access signal-cli's port |
| T-17-05 | Denial of Service | flap-storm triggers Signal rate limit / CAPTCHA | mitigate | `ALERT_MAX_SENDS_PER_HOUR=20` default cap; debounce (N=5 consecutive) prevents the cause; Pitfall 8 runbook if CAPTCHA does trigger |
| T-17-02 | Tampering | inbound Signal message triggers unintended action | mitigate | Sender whitelist in receive-loop.js (implemented in Plan 04); strict snooze grammar in snooze.js (Plan 02); unknown senders logged + dropped |
</threat_model>
