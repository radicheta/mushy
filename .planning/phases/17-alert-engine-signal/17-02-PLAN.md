      const m = text.trim().match(STRICT);
      if (m) {

        const durationMs = VALID_DURATIONS[m[2].toLowerCase()];

        "Valid durations: 30m, 1h, 2h, 4h, 8h, 24h" };

        perType
      };

    function transition(prev, event, now, config) {
      const next = structuredClone(prev);
      const actions = [];
      // Dispatch by event.type; update next; push actions.

    Key transition logic per event:

    - `humidity {value}`: Update `currentRh`, `lastRhMsgTs`. If `warmingUp` → ignore for rh/humidifier detectors. Else: if `isRhOob(value, config)` → OOB path (OK→PENDING→FIRING via oobN/oobWindowMin); if in-band and state is FIRING/PENDING → clear-count path (5 consecutive in-band required for FIRING→OK + recovery). Check humidifier-stuck on every humidity tick when humidifierOnSinceMs is set.
    - `sensor_health {level, message, values}`: level===1 sets warmingUp=true; level===0 clears. level===2 drives the 'sensor' alert through its own PENDING(>30s)→FIRING path. Warm-up suppression does NOT apply to sensor-ERROR.
    - `humidifier {value}`: 0→1 transition sets humidifierOnSinceMs=now, rhAtOn=currentRh. 1→0 transition clears, and if 'humidifier' alert is FIRING emit recovery.
    - `pi_liveness {wsConnected, rosConnected, humidifierLastMsgTs}`: merge into state. If `now - bootedAtMs < 60000` (startup grace) skip Pi-offline evaluation. Otherwise run isPiOffline and drive the 'pi' alert.
    - `tick`: pure evaluation — re-run isPiOffline, re-run isHumidifierStuck with current state. Used when no external events arrive but cooldown may have expired.
    - `snooze {alertType, untilMs}`: if alertType==='all', set snoozedUntil on every type. Else on one type. Do NOT change `state`; state stays FIRING while muted.
