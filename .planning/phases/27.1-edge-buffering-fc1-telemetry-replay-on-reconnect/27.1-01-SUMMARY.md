# Phase 999.1 Plan 01: Schema Migration + Shared Topic Manifest Summary

Wave-1 prerequisites for the edge buffering phase: the live Timescale `telemetry` table now gains a UNIQUE (topic, time) constraint via an idempotent boot-time migration in the bridge, and a shared 9-topic YAML manifest is the single source of truth for both the upcoming Python `fc_buffer` (Plan 02) and the JS bridge replay poller (Plan 03).

## What Was Built

**Schema migration (Task 1).** Two helpers extracted into `src/mission-control/bridge/src/schema_migration.js`:

- `applyTelemetryUniqueConstraint(pool)` — wraps `ALTER TABLE telemetry ADD CONSTRAINT telemetry_topic_time_unique UNIQUE (topic, time)` in a `DO $$ ... IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = ...) THEN ... END $$` block so re-running on every bridge boot is a no-op. Hypertable rule (UNIQUE must include partitioning column `time`) satisfied by the `(topic, time)` tuple.
- `findTopicTimeDuplicates(pool, limit=5)` — pre-flight scan returning rows for any `(topic, time)` pairs with `COUNT(*) > 1`.

`initDb()` in `index.js` now requires `./schema_migration` and, after creating the topic-time index, runs the dedupe scan and throws if duplicates exist (surfacing a real conflict instead of letting the Plan 03 backfill silently fail with the cryptic "no unique or exclusion constraint matching the ON CONFLICT specification" Postgres error). On a clean DB the migration runs and logs `[db] telemetry_topic_time_unique constraint ensured`.

**Shared topic manifest (Task 2).** `src/chambers/fc-core/config/buffered_topics.yaml` lists the canonical 9 buffered topics with `ros_topic`, `msg_type`, `bridge_topic`, `qos` per row. The 5 sensor topics use `qos: default`; the 4 actuator/control topics (`humidifier`, `humidifier_duty`, `humidity_target`, `pid_output`) use `qos: transient_local` to match the fc_controller publishers. `/fc1/camera/compressed` is deliberately excluded (D-11 — frame size unsuitable for the ring buffer; handled by Phase 22 / 999.10). `sensor_health` is excluded because `DiagnosticStatus` is not a scalar value.

## Tests

`src/mission-control/bridge/test/schema_migration.test.js` (6 tests, all green):

- Migration SQL contains the named constraint, the `UNIQUE (topic, time)` clause, and the `DO $$ ... IF NOT EXISTS ... pg_constraint ...` idempotency wrapper.
- Running `applyTelemetryUniqueConstraint` twice does not throw.
- `findTopicTimeDuplicates` returns `[]` when no rows; returns rows when duplicates exist.
- Query string matches the documented `GROUP BY 1,2 HAVING COUNT(*) > 1 ORDER BY n DESC LIMIT $1` shape; default limit is 5.
