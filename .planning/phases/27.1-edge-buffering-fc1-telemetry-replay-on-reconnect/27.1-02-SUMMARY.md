# Phase 999.1 Plan 02: fc_buffer Node Summary

**One-liner:** On-fc1 SQLite ring buffer + HTTP `/telemetry/since` replay endpoint as a new ROS2 node (`fc_buffer`), with all 9 buffered topics subscribed and camera traffic hard-excluded.

## What was built

`fc_buffer` is a Python rclpy node that:

1. Subscribes to all 9 entries in `config/buffered_topics.yaml` (RelativeHumidity / Temperature / Float32 / Bool, default + transient_local QoS).
2. Writes each message via `INSERT OR IGNORE INTO telemetry_buffer (topic, time_ns, value, extra)` to `/var/lib/fc-core/buffer.sqlite` (WAL mode). Single writer connection, serialised by `_db_lock`.
3. Runs an `http.server.ThreadingHTTPServer` on `100.96.239.75:8765` (parameterised — never `0.0.0.0`) handling `GET /telemetry/since?ts=<ns>&limit=<N>`. Bad ts/limit → 400; unknown path → 404. Output is `application/x-ndjson`, oldest-first, capped at `HTTP_LIMIT_CAP = 50000` rows.
4. Prunes rows older than `retention_seconds` (default 86400 s) every `prune_interval_seconds` (default 60 s) via a ROS timer.

The node is registered as a `console_script` in `setup.py`, launched alongside the rest of fc-core in `fc.launch.py`, and parameterised under a top-level `fc_buffer:` block in `fc_config.yaml`.

The systemd unit gets a new `ExecStartPre=/bin/bash -c 'install -d -o ubuntu -g ubuntu -m 0755 /var/lib/fc-core'` line **before** the existing tailscale0-wait — preserving Pitfall 7 (WAL sidecars need write-perm on the directory) without disturbing the documented tailscale0 race-mitigation.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug in plan-specified test arithmetic] test_pruner_evicts numbers**

- **Found during:** Task 2 GREEN
- **Issue:** Plan body §Task 1 specified `_prune(db, retention_seconds=86400, now_ns=3_000_000_000_000)` and asserted that rows at time_ns=1000 and 2000 would be evicted. The math doesn't work: `now_ns=3e12 ns ≈ 3000 s`, retention=86400 s, so cutoff = 3000 − 86400 = **−83400 s** in ns — i.e. negative. With cutoff < 0, the pruner deletes *nothing*, leaving all three rows. The third row at time_ns=3e12 (~3000 s old) is itself well within the retention window.
- **Fix:** Set `now_ns = 100_000 × 1_000_000_000` (100,000 s). Now cutoff = 100,000 − 86,400 = 13,600 s in ns. Rows at 1000 and 2000 ns are pre-cutoff and evicted; the row at `now_ns` survives.
- **Files modified:** `src/chambers/fc-core/fc_core/test/test_fc_buffer.py` (only the test_pruner_evicts function)
- **Commit:** included in `b016c77` (test scaffold) — the pruner test was rewritten before the GREEN run

**2. [Rule 2 — Auto-add: lazy ROS imports]**

- **Found during:** Task 1 RED (test infrastructure)
- **Issue:** Plan said to follow fc_pwm_driver pattern, which puts `import rclpy` and `from sensor_msgs.msg import …` at module top. That makes the module unimportable on dev hosts without ROS — exactly where the unit tests run.
- **Fix:** Helpers (`init_schema`, `_write_row`, `_prune`, `_serve_since`, `_load_topics`, `_extract`) live at module top with no rclpy/ROS imports. Class construction is gated behind `_make_fc_buffer_class()` and `_build_msg_class_map()`, both of which import ROS lazily. `main()` imports rclpy on entry. Pure helpers stay testable; live behaviour stays identical.
- **Files modified:** `src/chambers/fc-core/fc_core/fc_buffer.py` (structural)
- **Commit:** part of the GREEN landing (see Commit attribution below)

**3. [Rule 3 — Blocking: ThreadingHTTPServer call style]**

- **Found during:** Task 2 acceptance check
- **Issue:** First draft used a multi-line `ThreadingHTTPServer(\n    (self._http_bind, self._http_port), handler_cls\n)` call. The acceptance regex `ThreadingHTTPServer\(\(self\.[_a-zA-Z]*http_bind` requires the bind tuple on the same line.
- **Fix:** Single-lined the call. Behaviour unchanged; regex matches.
- **Files modified:** `src/chambers/fc-core/fc_core/fc_buffer.py`

**4. [Rule 1 — Comment containing forbidden literal]**

- **Found during:** Task 2 acceptance check
- **Issue:** Initial `DEFAULT_HTTP_BIND` comment said `# fc1 tailscale0 — never '0.0.0.0'`. The acceptance criterion `! grep -q "'0.0.0.0'"` is a substring match — it doesn't distinguish comments from code.
- **Fix:** Reworded comment to "never the wildcard interface". Same intent, no forbidden literal anywhere in the file.
- **Files modified:** `src/chambers/fc-core/fc_core/fc_buffer.py`
