    Execute a scripted soak: restart fc-core, capture `/fc1/sensor_health` echo for 40s, grep humidifier actuator events from journalctl. Record everything verbatim in the evidence file.

    1. Kick off the soak on fc1. Run these as a single SSH invocation to keep timing tight:
       ```bash
       ssh -o ConnectTimeout=30 fc1-ts "
         set -e
         source /opt/ros/jazzy/setup.bash
         source ~/mushroom_farm_ws/install/setup.bash
         export ROS_DOMAIN_ID=69
         # Clear journal cursor
         sudo systemctl restart fc-core
         RESTART_TS=\$(date --iso-8601=seconds)
         echo \"RESTART_TS=\$RESTART_TS\"
         # Capture sensor_health for 40s (should see WARN at ~0s and OK at ~20-25s)
         timeout 40 ros2 topic echo /fc1/sensor_health 2>&1 | tee /tmp/15-sensor-health.log || true
         echo '---HUMIDIFIER JOURNAL (first 30s post-restart)---'
         journalctl -u fc-core --since \"\$RESTART_TS\" --until \"30 seconds ago\" 2>/dev/null | grep -iE 'humidifier|warmup|warming' || echo 'no humidifier/warmup lines in window'
         echo '---TOPIC INFO---'
         ros2 topic info /fc1/sensor_health
       " 2>&1 | tee /tmp/15-soak.log
       ```
    2. Inspect `/tmp/15-soak.log` for these PASS signals:
       - Early in the echo stream: a `DiagnosticStatus` message with `level: 1` (WARN) and `message: warming up`
       - Later (within ~25s): a `DiagnosticStatus` with `level: 0` (OK) and `message: ok`
       - `ros2 topic info /fc1/sensor_health` prints `Type: diagnostic_msgs/msg/DiagnosticStatus`
       - The journalctl humidifier grep block does NOT contain `humidifier ON` or similar actuation logs in the first 20s window (it MAY contain a `WARMUP-CLEARED` log after 20s — that's expected)
