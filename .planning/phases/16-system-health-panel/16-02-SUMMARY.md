# Phase 16 Plan 02: Six-Light System Health Strip Summary

Added a new "System Health" object and view to the Mission Control fruiting-chamber plugin — a horizontal strip of six `makeStatusLight` instances showing live subsystem status at a glance.

## What Was Built

**New constant:** `HEALTH_ID = { namespace: 'fruiting-chamber', key: 'fc.health' }` alongside `CAMERA_ID`.

**New object type:** `fruiting-chamber.health` registered with `openmct.types.addType`.

**Root composition extended:** `HEALTH_ID` appended to the root folder's composition array so "System Health" appears in the MC tree under "Fruiting Chamber FC-1".

**New object provider branch:** `identifier.key === 'fc.health'` returns the System Health domain object.

**New view provider:** `fruiting-chamber.health-view` with a full `show()`/`destroy()` lifecycle. Six lights wired to real signals:

| Light | Label | Signal | Green | Grey | Red |
|-------|-------|--------|-------|------|-----|
| `lights.sensors` | Sensors | WS `sensor_health.level` | level=0 OK | no message in 10s or level=1 warm-up | level≥2 |
| `lights.cameraFeed` | Camera feed | `/health` `camera.*` | age<10s && subscribed | no frame yet or not subscribed | age≥10s && subscribed |
| `lights.humidifier` | Humidifier | `/health` `humidifier.last_msg_ts` | last_msg_ts within 30s | no ts or stale | never |
| `lights.bridge` | Bridge | `/health` HTTP response | 200 OK | — | fetch error |
| `lights.pi` | Pi reachable | `/health` `ros.connected` | true | — | false |
| `lights.grace` | Grace | WS `sensor_health.level` | level=0 | unknown or level=1 | never |

**Poll cadence:** 2000ms for `/health` (matches D-01 spec). Sensor/Grace lights also update on every incoming WS `sensor_health` message for sub-2s reaction time.

**Destroy lifecycle:** poll interval cleared, all six `makeStatusLight` instances destroyed, dedicated WS closed with reconnect guard disabled.

## Note for Plan 16-03

To open the System Health view in a browser, navigate to Mission Control at `http://<host>:8080`, expand "Fruiting Chamber FC-1" in the left tree, and click "System Health". The view renders the horizontal strip immediately. URL path will contain the encoded object key `fruiting-chamber:fc.health` in the hash fragment once opened — e.g. `http://elder-plops:8080/#/browse/fruiting-chamber:root?view=fruiting-chamber.health-view&...` (exact hash generated by OpenMCT on first navigation).

A hard-refresh (Ctrl+Shift+R) is needed on any browser that cached the previous `plugin.js` before the rebuild.
