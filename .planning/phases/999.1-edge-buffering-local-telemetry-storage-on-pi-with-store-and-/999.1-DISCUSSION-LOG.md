## Replay Protocol

| Option | Description | Selected |
|--------|-------------|----------|
| Bridge polls fc1 (Recommended) | fc1 exposes `/telemetry/since?ts=X`; bridge polls on gap detection. Stateless, idempotent, bridge already owns Timescale write path. | ✓ |
| fc1 pushes on reconnect | fc1 watches own connectivity; streams buffered points back via WS or replay topic. More state machine, harder idempotency across restart races. | |
| CycloneDDS history persistence | DURABILITY=PERSISTENT on relevant topics. Built-in but opaque, doesn't survive fc-core restarts. | |

**User's choice:** Bridge polls fc1 (recommended).

---

## Storage Substrate

| Option | Description | Selected |
|--------|-------------|----------|
| SQLite (Recommended) | WAL mode; PK on (topic, time_ns). stdlib, ~5MB/day, indexed since-X queries. | ✓ |
| Append-only JSONL | One file per UTC day. Simpler to inspect; no index, replay scans more bytes. | |

**User's choice:** SQLite (recommended).

---

## Topic Scope + Retention

| Option | Description | Selected |
|--------|-------------|----------|
| Capture-all + 24h ring (Recommended) | Subscribe to all fc1/* + future derived topics; evict >24h on periodic sweep. | ✓ |
| Capture-all + disk-pressure eviction | Hold until disk threshold (~1GB), then drop oldest. Maximum forensic value, less predictable. | |
| Opt-in per topic + 7d | Explicit YAML list; longer retention, smaller volume, manual maintenance. | |

**User's choice:** Capture-all + 24h ring (recommended).
**Note captured:** Camera topic explicitly excluded by name — frames are too large for the ring buffer's purpose (post-mortem of control loop), and Phase 22/999.10 already handle camera persistence.
