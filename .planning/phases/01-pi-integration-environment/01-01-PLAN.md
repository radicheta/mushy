**Step 1: Create the SSH setup runbook** at `docs/pi-setup/ssh-setup.md` with these exact sections and commands:

```markdown
# FC-1 Pi SSH Setup

## Prerequisites
- Raspberry Pi 4 running Ubuntu 24.04 (Noble) — per D-01, D-02
- Pi connected to LAN on 192.168.88.x subnet — per D-06
- Workstation on same LAN subnet

## Steps

### 1. Boot Pi and find its IP
From workstation:
  nmap -sn 192.168.88.0/24 | grep -B2 "Raspberry"
Or check router DHCP lease table.

### 2. Initial SSH (may need password)
  ssh ubuntu@<PI_IP>
Default Ubuntu user is `ubuntu`, default password is `ubuntu` (first boot forces password change).

### 3. Set static IP on Pi
Edit /etc/netplan/50-cloud-init.yaml (or equivalent):
  network:
    version: 2
    ethernets:
      eth0:
        dhcp4: no
        addresses: [192.168.88.XX/24]
        routes:
          - to: default
            via: 192.168.88.1
        nameservers:
          addresses: [1.1.1.1, 8.8.8.8]
Apply: sudo netplan apply

### 4. Copy SSH key from workstation
  ssh-copy-id -i ~/.ssh/id_ed25519.pub ubuntu@192.168.88.XX
If no ed25519 key exists:
  ssh-keygen -t ed25519 -C "mushy-workstation"

### 5. Add SSH config entry on workstation
Add to ~/.ssh/config:
  Host fc1
    HostName 192.168.88.XX
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519

### 6. Verify passwordless SSH
  ssh fc1 "hostname && uname -a"
Expected output: Pi hostname and Linux kernel info, no password prompt.

### 7. Disable password auth on Pi (optional hardening)
  sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
  sudo systemctl restart ssh
```

**Step 2: Guide the user** through each step above. Pause after step 1 to confirm Pi IP. Pause after step 6 to confirm passwordless SSH works.

Record the Pi's actual static IP in the runbook (replace XX with real value).

**1. Create `docs/pi-setup/wireguard-setup.md`** with:
- Section "Prerequisites": WireGuard installed on Pi (`sudo apt install wireguard`), server public key available, server endpoint known
- Section "Generate Pi Keys": `wg genkey | tee /etc/wireguard/private.key | wg pubkey > /etc/wireguard/public.key`
- Section "Fill Template": Document each variable in `wg0.conf.template`:
  - `${WG_PRIVATE_KEY}` — contents of `/etc/wireguard/private.key`
  - `${WG_SERVER_PUBLIC_KEY}` — provided by WireGuard server admin
  - `${WG_SERVER_ENDPOINT}` — server's public IP or hostname
  - `${WG_IP}` — Pi's assigned IP on the 172.16.10.0/24 mesh (e.g., 172.16.10.X)
- Section "Deploy": Copy filled config to `/etc/wireguard/wg0.conf`, `sudo systemctl enable wg-quick@wg0`, `sudo systemctl start wg-quick@wg0`
- Section "Verify": `sudo wg show` should list peer with handshake; `ping 172.16.10.1` (server) should succeed
- Section "Troubleshooting": Common issues (firewall, NAT traversal, server unreachable)
- Note at top: "VPN is not required for Phase 1 to succeed. LAN SSH access is sufficient. VPN connects when server is reachable."

**2. Create `scripts/pi-deploy/wg-setup.sh`** — a bash script that:
- Takes environment variables `WG_PRIVATE_KEY`, `WG_SERVER_PUBLIC_KEY`, `WG_SERVER_ENDPOINT`, `WG_IP`
- Reads `wg0.conf.template` from repo root
- Substitutes variables using `envsubst`
- Copies result to `/etc/wireguard/wg0.conf` (requires sudo)
- Enables and starts `wg-quick@wg0`
- Runs `sudo wg show` to display status
- Script must have `set -euo pipefail` and check that all 4 env vars are set before proceeding
- Must print clear error if any var is missing

**3. Verify `wg0.conf.template`** already has the correct structure (it does — [Interface] with PrivateKey, Address, ListenPort; [Peer] with PublicKey, AllowedIPs, Endpoint, PersistentKeepalive=25). No changes needed to template unless `${WG_IP}` is missing — current template uses `${WG_IP}/24` in Address field, which is correct.
