Run the following commands on the Pi via SSH and capture output. Claude should run these commands and create the documentation based on results.

**Step 1: Confirm OS version**
```bash
ssh fc1 "cat /etc/os-release"
```
Expected: `VERSION_ID="24.04"` and `NAME="Ubuntu"` (per D-02).
If NOT Ubuntu 24.04: STOP. User must flash Ubuntu 24.04 Noble before proceeding. Document what was found.

**Step 2: Confirm Pi hardware model**
```bash
ssh fc1 "cat /proc/device-tree/model"
```
Expected: Contains "Raspberry Pi 4" (per D-01).

**Step 3: Check kernel version**
```bash
ssh fc1 "uname -r"
```
Document the kernel version — needed for GPIO compatibility assessment.

**Step 4: Install RPi.GPIO and test import**
```bash
ssh fc1 "sudo apt update && sudo apt install -y python3-pip python3-dev"
ssh fc1 "pip3 install RPi.GPIO 2>&1"
ssh fc1 "python3 -c 'import RPi.GPIO as GPIO; print(\"RPi.GPIO version:\", GPIO.VERSION); print(\"Board revision:\", GPIO.RPI_INFO)'"
```
If RPi.GPIO import fails: Try `rpi-lgpio` as fallback:
```bash
ssh fc1 "pip3 install rpi-lgpio 2>&1"
ssh fc1 "python3 -c 'import RPi.GPIO as GPIO; print(\"rpi-lgpio loaded, version:\", GPIO.VERSION)'"
```

**Step 5: Test basic GPIO access (read-only, no wiring needed)**
```bash
ssh fc1 "python3 -c '
import RPi.GPIO as GPIO
GPIO.setmode(GPIO.BCM)
GPIO.setup(4, GPIO.IN)  # DHT22 pin - read only, safe
val = GPIO.input(4)
print(\"GPIO4 read value:\", val)
GPIO.cleanup()
print(\"GPIO access: OK\")
'"
```
This tests that the user running the script has permission to access GPIO. If permission denied: `sudo usermod -aG gpio ubuntu` and retry.
