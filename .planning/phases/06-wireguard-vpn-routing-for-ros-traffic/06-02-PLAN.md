    This is a human-action checkpoint. Claude cannot access the pfSense WebGUI.

    The user must add FC-1 Pi as a WireGuard peer in pfSense:

    1. Get the Pi public key: run `ssh fc1 "sudo cat /etc/wireguard/public.key"` or read from Plan 01 SUMMARY
    2. Open pfSense WebGUI: https://10.68.155.1
    3. Navigate to: VPN > WireGuard > Peers
    4. Click "+ Add Peer" with these values:
       - Tunnel: tun_wg0 (the "mossrock" tunnel)
       - Description: FC-1 Pi
       - Public Key: (paste the Pi public key)
       - Allowed IPs: 172.16.10.5/32
       - Dynamic Endpoint: checked
    5. Click Save, then Apply Changes
    6. Verify tunnel establishes: `ssh fc1 "sudo wg show wg0"` — expect "latest handshake:" with timestamp
    7. Test connectivity: `ssh fc1 "ping -c 2 172.16.10.1"` — expect 0% loss
  </action>
  <verify>

  <action>
    On elder-plops (local machine), enable persistent WireGuard autoconnect:

    1. Enable autoconnect for the existing wg0 NetworkManager connection:
       ```bash
       sudo nmcli connection modify wg0 connection.autoconnect yes
       sudo nmcli connection modify wg0 connection.autoconnect-priority 5
       ```

    2. Ensure wg0 is currently up:
       ```bash
       sudo nmcli connection up wg0
       ```

    3. Verify mesh connectivity — all three nodes must reach each other:

       From elder-plops:
       ```bash
       ping -c 2 172.16.10.1   # pfSense VPN gateway
       ping -c 2 172.16.10.5   # FC-1 Pi
       ```

       From Pi (via SSH):
       ```bash
       ssh fc1 "ping -c 2 172.16.10.1"   # pfSense
       ssh fc1 "ping -c 2 172.16.10.3"   # elder-plops
       ```

    If any ping fails, troubleshoot:
    - Check pfSense firewall rules on the WireGuard interface (must allow traffic from 172.16.10.0/24)
    - Check `sudo wg show` on both machines for handshake status
    - Check that pfSense peer for elder-plops has AllowedIPs including 172.16.10.3/32
  </action>

    - `ssh fc1 "ping -c 1 172.16.10.3"` exits 0 (Pi -> elder-plops)
