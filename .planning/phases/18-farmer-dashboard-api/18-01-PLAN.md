# Plan 18-01: Read-only /farmer/summary endpoint

**Retrofit plan** — captured after implementation. Work was shipped inline
during a planning session; this doc exists so GSD state matches reality.

## Goal

Expose a single read-only JSON endpoint on the mushy bridge returning the
current chamber snapshot in a shape the farmOS-hosted dashboard can consume.

## Tasks

1. **Add latest-value cache.** Module-level `latestTelemetry` object in
   `src/mission-control/bridge/src/index.js` holding `{ humidity, temperature,
   co2, humidifier }`, each either `null` or `{ value, timestamp }`.

2. **Populate cache from existing subscriptions.** Append one line to each of
   the existing humidity / temperature / co2 / humidifier subscription
   callbacks so the cache stays current alongside the WebSocket broadcast.
   No new subscriptions, no QoS changes.

3. **Add `GET /farmer/summary` route.** Composes the response from:
   - `CAMERA_ID` (existing) → `chamber_id`
   - `Date.now()` → top-level `timestamp`
   - `latestTelemetry.*` → `sensors` + `actuators`
   - `lastSensorHealthBroadcast` (existing from Phase 16.1) → `sensor_health`
   - `lastFrameTime` + `cameraSubscription` (existing) → `camera`

4. **Rebuild + verify.** `docker compose up -d --build bridge` (per the memory
   rule — don't trust cached image). Curl the endpoint on elder-plops, confirm
   JSON shape and live values.

## Verification

Endpoint returns a valid JSON object with the agreed shape on the live
elder-plops bridge, with non-null sensor values during normal chamber
operation.

## Non-goals

- No farmOS-side integration code (delegated to Zoy-side).
- No CORS reconfiguration (proxy-through-farmOS assumed; revisit if Zoy
  opts for browser-direct fetch).
- No schema versioning, auth, or alert history feed (see CONTEXT.md
  "Deferred Ideas").
