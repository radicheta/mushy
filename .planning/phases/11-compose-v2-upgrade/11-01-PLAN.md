This task performs the production cutover on elder-plops. There will be brief downtime (~30 seconds) while containers are recreated.

**Step 1: Pre-flight check.** Verify current state before touching anything:
```bash
docker-compose version          # expect: 1.29.2
docker ps --format "{{.Names}}" | grep mushy   # expect: mushy_bridge_1, mushy_openmct_1, mushy_timescale_1
docker volume ls | grep timescale-data          # expect: mushy_timescale-data (confirm named volume exists)
```

Also run the research-recommended pre-cutover check for any system-level v1 references:
```bash
grep -r docker-compose /etc/systemd/ /etc/cron* ~/.bashrc ~/.zshrc 2>/dev/null || echo "No system-level docker-compose references found"
```

**Step 2: Install docker-compose-v2 via apt:**
```bash
sudo apt update
sudo apt install -y docker-compose-v2
```

Verify v2 is available:
```bash
docker compose version   # expect: Docker Compose version v2.40.x
```

**Step 3: Purge docker-compose v1:**
```bash
sudo apt purge -y docker-compose
```

Verify v1 is gone:
```bash
which docker-compose && echo "FAIL: v1 still on PATH" || echo "PASS: v1 removed"
```

**Step 4: Bring down the current v1 stack and recreate under v2:**
```bash
cd /mnt/slime-kingdom/opt/mushy
docker compose down                        # stops + removes old v1-named containers
docker compose up -d --build bridge        # recreates all services with v2 hyphen naming, rebuilds bridge image
```

**Step 5: Clean up any orphan containers from v1:**
```bash
docker compose up -d --remove-orphans
```

Also manually remove any leftover stopped v1 containers if they exist:
```bash
docker rm mushy_bridge_1 mushy_openmct_1 mushy_timescale_1 2>/dev/null || true
```

**Step 6: Verify all 3 services are running with v2 names:**
```bash
docker compose ps                          # expect: mushy-bridge-1, mushy-openmct-1, mushy-timescale-1 all running
docker ps --format "{{.Names}}" | grep mushy   # expect: hyphen names only, no underscore names
```

**Step 7: Verify TimescaleDB data survived (INFRA-02):**
```bash
docker compose exec timescale psql -U postgres -c "SELECT count(*) FROM telemetry;" 2>/dev/null || docker compose exec timescale psql -U postgres -c "\\dt" 2>/dev/null
```
Any non-zero row count or table listing confirms data integrity.

**Step 8: Verify Mission Control is reachable:**
```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080   # expect: 200
```

**Step 9: Check bridge logs for ROS2 connection:**
```bash
docker compose logs --tail=20 bridge   # expect: no crash loops, should show ROS2 topic subscription messages
```
