## What Was Built

**`src/confirm/strain-ask-back.js`** (pure module, no IO):

- `renderStrainAskBack(seenCode, nearest)`: ASCII/no-em-dash per-encounter prompt. With nearest: "Saw strain 'XYZ' -- not in the active list. New strain, or did you mean SHI? Reply YES ...". Without nearest: concise new-strain prompt.
- `parseStrainAskBackReply(text)`: Returns `{ kind: 'confirm_new' }` for YES/confirm/si/ok, `{ kind: 'correction', code: 'SHI' }` for bare strain codes (2-4 chars) or "no, CODE" form, `{ kind: 'unknown' }` otherwise. CODE_RE limited to 2-4 chars to avoid matching common words like "maybe".

**`src/confirm/outbound-confirm.js`** -- `send_strain_ask_back` case:

- DM-only dispatch (mirrors `send_ask_back`). Builds body via `renderStrainAskBack(extras.seenCode, extras.nearest)`. Intent='ask_back', relatedDraftId=draftRow.id, no quote. Missing target -> `{ ok:false, reason:'no_target' }`, no throw.

**`src/receive-loop.js`** -- strain-pending intercept:

- When `draftRow.needs_review_reason === 'strain_unknown_pending_confirm'` and `extractionDb` is wired, routes inbound reply through `parseStrainAskBackReply` first.
- `confirm_new` (YES): calls `updateDraftStatus(..., { needs_review_reason: 'strain_confirm_approved' })` then `confirmDraft` + `send_confirm_ack`.
- `correction` with curated target: rewrites `draft_json.species_code` via `updateDraftStatus(..., { draft_json: updatedDraftJson })` then `confirmDraft` WITHOUT approval marker (no mint).
- `correction` with non-curated target: re-dispatches `send_strain_ask_back`, does not confirm.
- `unknown` reply: falls through to NOOP -> capture pipeline (no hold, no error).

**`src/farmos/commit-watchdog.js`** -- per-draft rowCtx:

- Builds `rowCtx = Object.assign({}, ctx, { createMissingFungiType: !!(ctx.createMissingFungiType) || lockedRow.needs_review_reason === 'strain_confirm_approved' })` before calling `commitRouter.commit`.
- T-54.1-06 mitigation: this is the sole write site. Shared `ctx` default stays false. Only an explicitly approved draft mints.

## Deviations from Plan

**1. [Design - CODE_RE scope] Correction parser limited to 2-4 char codes**

The plan did not specify a size limit for recognized strain codes. I applied a 2-4 char constraint matching the curated set shape (SHI, KOY, LIMA, SH2 = 2-4 chars). This prevents common words like "maybe" (5 chars), "nope", etc. from being misclassified as correction codes. The constraint is documented in the module.

**2. [Design - unknown reply fallthrough] Unknown reply on strain-pending draft falls through**

The plan says "unknown -> never mint". I chose to fall through to the NOOP path (which leads to the capture pipeline) rather than holding or error-replying. This preserves existing behavior for messages that aren't recognizable as strain replies -- they proceed as fresh captures. No new ask-back is sent for truly unrecognized input.

**3. [Design - extractionDb parameter] New optional param in createReceiveLoop**

Added `extractionDb = null` as an optional parameter to `createReceiveLoop`. All existing callers pass no value, so back-compat is maintained. When absent, the strain-pending branch is skipped (the guard checks `extractionDb && typeof extractionDb.updateDraftStatus === 'function'`).
