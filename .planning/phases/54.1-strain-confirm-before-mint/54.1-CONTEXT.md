<domain>
## Phase Boundary

When extraction yields a fungi_type strain code that is **not an exact match** to the
curated active strain set, hold it for a farmer double-check **before** minting a
taxonomy term. Two paths:

- **Live capture:** per-encounter ask-back via the Phase 39 confirm-loop ("saw 'XYZ' --
  new strain or did you mean <nearest>?"). YES mints + proceeds; correction remaps.
- **Backfill (async, bulk):** BATCHED. Collect unknown codes across the run, hold those
  drafts as `needs_review` (do NOT commit, do NOT mint), send ONE Signal message listing
  them; a follow-up pass mints confirmed-new terms, remaps corrections, and commits the
  held drafts.

This replaces the blind auto-mint first cut that polluted dev farmOS with extraction
variants (LIM for LIMA, SHIITAKE for SHI, OYS/KOY for POY). Unblocks a clean Cycle-1 /
Phase-55 receipt.

**Current state of the code (verified 2026-05-25):** blind-mint is already gated OFF
(`backfill-notebook.js:356` sets `createMissingFungiType: false`; comment at :344).
Today an unknown strain fails `fungi_type_not_found` at commit. This phase adds the
confirm gate so unknowns are *held and asked about* instead of failing.

### In scope
- A strain resolver: exact-match an extraction code against the curated 14-code set.
- Backfill path: unknown-strain collection -> `needs_review` hold (no commit, no mint) ->
  one batched Signal message -> follow-up confirmed-mint + remap + commit pass.
- Live path: hook the per-encounter ask-back into the Phase 39 confirm-loop.
- Call `ensureFungiTypeUuid(create=true)` ONLY after farmer confirmation.

### Out of scope (deferred / not this phase)
- Deleting the 4 bogus dev-farmOS terms (bot gets 403; needs a farmOS admin — see below).
- Any fuzzy/auto-canonicalization that silently maps a code to a near neighbor.
- Wiping dev backfill test assets (operator runbook concern, not code).
</domain>

<decisions>
## Implementation Decisions (LOCKED with Santi 2026-05-25)

### Detection
- **Exact-match against the CURATED active set only**, NOT "any existing fungi_type term in
  farmOS". The curated set is the 14 codes in `tenants/mossrock/strains.yaml`
  (SHI SH2 KOY MAI MALI KOS DT CAS CAZ WIN ALM MOR BP LIMA), loaded as `config.strains`.
  Rationale: dev farmOS already contains undeletable pollution terms (LIM/SHIITAKE/OYS/CAR);
  matching live terms would let a re-extracted "LIM" exact-match the bogus term and silently
  pass. Match the source-of-truth list instead.
- **NO fuzzy auto-resolve.** Never silently mis-map a real new strain that is one char from
  an existing one. An unknown code is held for the farmer, period.

### Live capture path
- On an unknown strain, ask via the Phase 39 confirm-loop / ask-back:
  "Hey, I saw 'XYZ' on today's log -- new strain, or did you mean <nearest known>? Confirm or
  correct." YES -> mint term (`ensureFungiTypeUuid create=true`) + proceed. Correction ->
  remap to the canonical code (no mint).

### Backfill path (async, bulk)
- BATCHED confirm. Collect all unknown strain codes across the run; hold those drafts as
  `needs_review` (do NOT commit, do NOT mint). Send ONE Signal message listing them
  ("Backfill found new codes: LIM, SHITAKE, OYS. Real new strains, or typos for LIMA/SHI/POY?").
- On farmer reply, a follow-up pass mints the confirmed-new terms, remaps corrections, and
  commits the held drafts.
- The auto-confirm short-circuit (`flipDraftToConfirmed`, `bulk_backfill_santi`) must NOT
  fast-confirm a draft whose strain is unknown -- those go to `needs_review` hold instead.

### Mint mechanism
- `ensureFungiTypeUuid(client, name, {create})` already exists (`fungi-type-cache.js:61`).
  The confirm flow calls it with `create=true` ONLY after farmer confirmation. Nothing else
  flips `createMissingFungiType` to true.

### Claude's Discretion
- Exact module/file layout for the resolver and the backfill batch-hold + follow-up pass.
- Wording of the batched Signal message (must honor [[feedback_no_em_dashes_in_artifacts]]
  and [[feedback_round_farmer_numbers]]).
- How the follow-up confirmed-mint pass is invoked (new subcommand vs flag on backfill CLI).
- Test fixtures and how to simulate the LIMA/SHI/POY variant cases.
</decisions>

## Specific Ideas

- Variant cases the resolver must catch (from Cycle-1 real data): LIM (truncation of LIMA),
  SHIITAKE/SHITAKE (full name for SHI), OYS (oyster synonym for POY), KOY (P/K OCR confusion
  for POY). Note POY itself is the CSV ground-truth code but is NOT in the curated 14-set and
  has no dev-farmOS term -- so POY is itself an "unknown" under exact-match and must be held.
- The receipt CSV "misses" were almost entirely these variant mismatches, not extraction
  errors -- canonicalization is the gap, semantic accuracy is high.
- Backfill is santi-only, dev-only, with a prod-guard already enforced upstream.
