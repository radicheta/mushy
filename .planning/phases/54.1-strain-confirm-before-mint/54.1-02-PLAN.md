<objective>
Add the strain-confirm gate to the backfill path. In `scripts/backfill-notebook.js`'s
`processDraftsForCapture` bulk loop: before the auto-confirm short-circuit, resolve each
draft's strain against the curated set (Plan 01's `resolveStrain` + `config.strains`).
Unknown-strain drafts are NOT flipped to confirmed and NOT committed -- they are held as
`needs_review` with reason `strain_unknown_pending_confirm`, and their codes are collected.
After the loop, send ONE batched Signal message listing the unknown codes with nearest-known
suggestions ("Backfill found new codes: LIM, SHITAKE. Real new strains, or typos for
LIMA/SHI?"). A new follow-up subcommand script `scripts/backfill-confirm-strains.js` parses
the farmer's reply, mints the confirmed-new terms via `ensureFungiTypeUuid(create=true)`,
remaps corrections to canonical codes, and commits the held drafts.

Purpose: This replaces the blind auto-mint that polluted dev farmOS. `create=true` is
passed ONLY inside the follow-up pass, ONLY for farmer-confirmed-new codes -- the main
backfill loop keeps `createMissingFungiType: false` (backfill-notebook.js:356 unchanged).

Output: gated bulk loop + batched message in backfill-notebook.js; new
backfill-confirm-strains.js follow-up pass; Jest coverage for both.
</objective>
