## Background

2026-05-12: Don Santiago attested Plan 07 PASS on a 2-curated-fixture eval. Within an hour, the first real prod inoc session via Signal (1 audio + 2 logsheet photos + 1 butt-dial) ran 0/4 through the live alerter. Investigation surfaced:

1. **Whisper GPU drift** (commit-of-fix: container restart 2026-05-12 18:58). Container had been up 5 days; `nvidia-smi` inside the container returned `Failed to initialize NVML: Unknown Error` despite host driver being fine. `/health` did not load the model -- only verified FastAPI was up -- so the healthcheck stayed green while every /transcribe returned 500. **Fake-green healthcheck is the durability bug**; the GPU drift itself is benign once detected.

2. **Pipeline image-wire bug** (commit-of-fix: a04a6bc 2026-05-12). pipeline.js:176 passed `attachmentPaths` (filesystem path strings) to extractor.extract, but multimodal.buildContentBlocks expected `{data, media_type}` base64 blocks. Result: every image silently skipped -> extractor saw empty prompt -> schema_invalid on every photo-only message. Latent since Plan 05 (862a73a, ~17h old when surfaced). Plan 07 eval harness (eval/extraction/mushdatadump.test.js) did not catch it because it calls readImageToBase64 directly, bypassing pipeline.js. **Harness-vs-pipeline parity is the durability bug**; the wire bug itself is fixed.

3. **Extractor species-vocab gap**: replay of the prod audio capture (transcript clearly says "winecap") coded the species as **CAS** instead of **WIN**. Small but real -- vocab needs common-name->code lookups for the species the system actually deals with.

4. **Real-data missing from ship-gate denominator**: Plan 07's 2-curated-photo PASS was structurally incapable of predicting the live behavior. A real-session fixture must be in the denominator before any PASS attestation.

## Task 1: Deep whisper /health

**File:** `src/whisper-transcribe/main.py`

Change `/health` to lazy-load the model on first call (or warm it at startup with a startup-event hook) and to perform a 1-second synthetic transcription before returning 200. On model-load failure or transcription failure return 503 with `{"status":"degraded","reason":"<short>"}`. Update the Dockerfile healthcheck and compose service healthcheck if needed -- the existing curl-based healthcheck is fine, just the endpoint semantics change.

## Task 2: Harness-pipeline parity

**File:** `src/agents/alerter/test/eval/extraction/mushdatadump.test.js`, `fixtures-loader.js`

The harness must call the same image-loading path the live pipeline calls. Two options:

  - **Option A (preferred):** Import `loadImageBlocks` from `src/extraction/pipeline.js` (export it from pipeline.js if not already) and use it in the harness.
  - **Option B:** Have the harness call a thin wrapper that mirrors pipeline.js's captures-construction. Same intent.

Either way, a regression in pipeline.js image-loading should fail the harness rather than slip through.

Add a regression test under `src/agents/alerter/test/extraction/` that instantiates the real pipeline (with a stub DB + stub outbound dispatcher), feeds it a captureCtx with `attachmentPaths: [<real jpeg path>]`, and asserts that the extractor receives non-empty image content blocks. This is the test that would have caught the 2026-05-12 bug.

## Task 3: Real-session fixture in ship-gate

**Files:** `src/agents/alerter/test/eval/extraction/fixtures-loader.js`, harness driver

Prod fixtures are structured per-session subdirectories (e.g., `2026-05-12_inoc_santi/`) containing audio + images + a MANIFEST.md. The harness loader needs to:
  - Treat each per-session subdir as ONE capture context (audio transcribed via whisper, images attached, all fed in one extractor.extract call)

Decision (Plan 09 discuss output): treat per-session subdirs as **one** capture (matches live pipeline behavior where each Signal message is one capture). Score the prod corpus on a different bar than curated (suggest: schema_conformance >= 90% AND no false PASS-with-zero-drafts).
