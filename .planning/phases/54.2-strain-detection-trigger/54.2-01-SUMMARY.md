# Phase 54.2 Plan 01: Foundational Wiring Seams Summary

**One-liner:** Lifted farmosClient into extraction pipeline + added send_strain_ask_back dispatch case + two STRAIN-08 source-level guards.

## What Was Built

Two foundational seams that Wave 2 (strain-detection gate) depends on:

**Seam 1 -- farmosClient DI (index.js):** The extraction pipeline previously received no farmOS client. `farmos.createFarmosClient` was lifted from inside the commit-watchdog `if` block (where it was scoped after the pipeline at ~:331) to ABOVE the `createExtractionPipeline` call. `farmosClient` is now a `let` variable initialized to null, assigned only when credentials are present, and forwarded into the pipeline. The commit-watchdog block reuses the same instance (no duplicate construction). When credentials are absent, `farmosClient` is null and a WARN is logged; the pipeline gate (Wave 2) guards `if (farmosClient)` and skips.

**Seam 2 -- send_strain_ask_back dispatch (extraction/outbound.js):** The extraction dispatcher had no `send_strain_ask_back` case -- the case existed only in `confirm/outbound-confirm.js` (a different dispatcher injected into the receive loop). Without this case, a pipeline dispatch would throw `unknown_side_effect` (the eb8332b bug class). Added the case using Option (b): pipeline pre-renders the batched body into `draftRow.farmer_facing_preview`; the case routes through the existing `sendAskBack` 2-arg path unchanged -- identical pattern to `send_starting_seq_askback`.

**STRAIN-08 wiring guards (startup-wiring.test.js):** Two source-level guards added to the Phase 54.1 precedent file. Guard 1 (fs-reads `src/index.js`, regex-matches `createExtractionPipeline({...})`, asserts `farmosClient` is in the object body) -- fails if Seam 1 is reverted. Guard 2 (fs-reads `src/extraction/outbound.js`, asserts `case 'send_strain_ask_back'` is present) -- fails if Seam 2 is reverted. These catch the DI-drop / missing-case class that injected-fake unit tests pass green on.
