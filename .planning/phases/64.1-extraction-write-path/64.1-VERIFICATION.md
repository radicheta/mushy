## Database safety

The test hard-refuses to run against anything but the throwaway `:5434`
postgres: it consumes the session-scoped `pool` fixture from
`tests/conftest.py` (which itself only ever connects to `TEST_TIMESCALE_HOST`/
`TEST_TIMESCALE_PORT`, defaulting to `5434`, and skips entirely if that host
is unreachable), and additionally asserts at the top of the test body
(`_assert_not_prod_port`) that the pool's `conninfo` does not contain `5432`
before sending a single byte. This is load-bearing, not a comment: a draft
that reaches `confirmed` on the shared TimescaleDB is picked up by the live
Node commit watchdog and written to the real farm's production farmOS.

### Output — RUN 2026-08-17, PASSED (twice, reproducibly)

Run against real `claude-sonnet-4-6` and the throwaway postgres on `:5434`.
Two consecutive runs, both green (17.8s / 17.2s) — worth stating because the
model is non-deterministic, so a single pass would not have been evidence of
much.

**It did not pass first time. It caught two real production bugs**, both
invisible to the 1084-test hermetic suite and to twelve reviews, and both the
same root cause: a test fake whose shape disagreed with the real collaborator.

1. `'SeedingSession' object has no attribute 'get'` — `pack_result` returned
   validated Pydantic models where every consumer, and Node, expects plain
   dicts. Fixed in `964382e`. `jsonb` persistence would have failed next
   regardless.
2. `Object of type datetime is not JSON serializable` — the in-flight draft
   handed to the prompt is a raw DB row, so `created_at`/`updated_at` are
   datetimes. This is the **continuity path**: a farmer's follow-up to an open
   draft, i.e. the multi-message inoculation session, the most common real
   intake shape on this farm. The single-message path worked fine, which is
   why nothing noticed. Fixed in `0c76d76`.

Bug 2 surfaced partly by luck — the live-fire had inherited a leftover
`awaiting_farmer` draft for the shared test recipient and took the continuity
path by accident. The gate now uses a dedicated sender and clears it first, so
which path it exercises is deterministic rather than a coin flip.

### What this run proves, and what it does not

Proves: real multimodal fusion of audio + photographed paper log + text
follow-up into one `seeding_session`; 11 children across 5 parents as the
design specified; the per-session SEQ counter running across groups rather
than restarting per strain (SHI 1-3, then KOY continuing 4-11), which matches
the documented ground truth that KOY starts at 4 on 2026-05-22; `origin='python'`
on a real row; and **D-1 end to end** — the confirm prompt was actually sent,
which production Node does not do.

Does NOT prove: batch mode, or the starting-SEQ reply. This fixture takes
neither path, and both had Critical defects found by inspection alone during
the whole-branch review. The gate is a floor, not a ceiling. Extending it to
feed a SEQ reply back in would close the larger of the two gaps.
