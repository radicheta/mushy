  <read_first>
    - .planning/phases/09-connectivity-boot-stability/09-CONTEXT.md §D-13
    - scripts/pi-deploy/fc-core.service (confirm tailscaled ordering is deployed)

  <what-automated>
    Nothing automated — requires physical presence at the farm to pull the Pi power
    plug (D-13: cold boot must be a real plug-pull, not `sudo reboot`).
  </what-automated>
  <how-to-verify>
  **Pre-condition:** Pi is running at the farm on 4G MiFi. Tailscale SSH reachable.

  **Step 1 — Record pre-pull state:**
  ```bash
  ssh fc1 'systemctl show fc-core -p NRestarts,ActiveState'
  # Record current NRestarts value (should be 0 from prior ops)
  ssh fc1 'journalctl -u fc-core.service -n 5 --no-pager'
  # Record current tail of journal
  ```

  **Step 2 — Physical plug pull:**
  - Physically unplug Pi power at the farm.
  - Wait 10 seconds.
  - Plug power back in.
  - Note the exact wall-clock time of plug-in.

  **Step 3 — Wait for Pi to come online:**
  On elder-plops, poll Tailscale until fc1-ts appears:
  ```bash
  # On elder-plops — run repeatedly until fc1 responds
  until tailscale ping 100.96.239.75 --timeout 5s 2>/dev/null; do
    echo "$(date): waiting for fc1..."; sleep 5
  done
  echo "$(date): fc1 Tailscale up"
  ```

  **Step 4 — Check fc-core restart count:**
  ```bash
  ssh fc1 'systemctl show fc-core -p NRestarts,ActiveState'
  # PASS criterion: NRestarts=0, ActiveState=active
  ssh fc1 'journalctl -u fc-core.service -b --no-pager'
  # Look for: "fc-core: tailscale0 ready (attempt N)" in ExecStartPre output
  # Must NOT contain: "Started FC-1" appearing more than once (= restart)
  ```

  **Step 5 — Time from plug-in to active:**
  ```bash
  ssh fc1 'systemctl show fc-core -p ActiveEnterTimestamp,InactiveExitTimestamp'
  # Calculate delta: time from InactiveExitTimestamp (first start attempt)
  # to ActiveEnterTimestamp (reached active). Should be <90s total boot.
  ```

  **Pass criteria for TDEBT-03 (criterion 3):**
  - NRestarts=0 on journalctl -b (this boot only)
  - ActiveState=active
  - Journal shows ExecStartPre "tailscale0 ready" message before ExecStart
  - Journal does NOT show multiple "Started FC-1" entries

  **Failure mode to watch for:** If NRestarts>0, collect full journal from
  this boot (`journalctl -u fc-core.service -b --no-pager`) and note which
  step failed. This would indicate ExecStartPre timeout is shorter than
  tailscaled needs at boot on this hardware — revisit poll duration.
  </how-to-verify>
  <acceptance_criteria>
    # Run after Task 1 completes — evidence commands
    ssh fc1 'systemctl show fc-core.service -p NRestarts' | grep -q 'NRestarts=0'
    ssh fc1 'systemctl is-active fc-core' | grep -q '^active$'
    ssh fc1 'journalctl -u fc-core.service -b --no-pager' | grep -q 'tailscale0 ready'
  </acceptance_criteria>
