Node's exact backoff schedule (bridge-client.js:15, 49, 79-80): `backoffMs` starts at 1000. On
close, the client waits the CURRENT value, then doubles it capped at 30000. On a successful open
it resets to 1000. The wait sequence across consecutive failures is therefore:
  **1s, 2s, 4s, 8s, 16s, 30s, 30s, …**  (16000×2 = 32000, capped to 30000)

`/health` shape and its three cases (bridge-client.js:21-40, 67-77):
- poll OK → `{ws_connected: True, ros_connected: bool(h.ros.connected), humidifier_last_msg_ts:
  h.humidifier.last_msg_ts or None, fc1_last_msg_ts: h.fc1.last_msg_ts or None, now_ms}`
- poll FAILS → same shape but `ros_connected=False` and both timestamps `None` — and
  **`ws_connected` stays True**. The socket is up; only the health data is unknown. Emitting
  False here would trip the pi-offline ws branch on a transient health blip.
- ws CLOSES → `ws_connected=False`, and the other three fields come from the LAST CACHED health
  snapshot, not from None. Losing the socket does not mean losing what we last knew.

Health poll cadence is 10s (bridge-client.js:56), started on ws open, stopped on close.

```python
"""
chamber/ws_client.py -- ROS-bridge WS client. Port of bridge-client.js.

Two decisions worth stating:

1. The backoff is HAND-ROLLED, not delegated to the websockets library's
   reconnect iterator. SC1 (pi-offline fires within the configured window)
   depends on reconnect timing, and Phase 64 replays real traffic against both
   stacks -- so the schedule has to be Node's 1s->30s doubling exactly, not
   whatever the library defaults to this release.

2. The backoff schedule and the liveness payload are pure functions, so the
   parity-critical behaviour is testable without a socket.
"""

from __future__ import annotations

import logging

logger = logging.getLogger(__name__)

# bridge-client.js:11-12 (minBackoffMs / maxBackoffMs defaults)
MIN_BACKOFF_MS = 1_000
MAX_BACKOFF_MS = 30_000


def next_backoff_ms(current_ms: int) -> int:
    """Double the backoff, capped. Port of bridge-client.js:80.

    Node waits the CURRENT value and then advances, so the wait sequence from a
    fresh client is 1s, 2s, 4s, 8s, 16s, 30s, 30s, ... (32s clamps to 30s).
    """
    return min(current_ms * 2, MAX_BACKOFF_MS)


def _dig(payload: dict, key: str, field: str):
    """Safely read payload[key][field]; None if absent or the wrong shape."""
    block = payload.get(key)
    if not isinstance(block, dict):
        return None
    return block.get(field)


def parse_health(payload: dict | None, now_ms: int, ws_connected: bool = True) -> dict:
    """Build a liveness event from a /health body. Port of bridge-client.js:27-38, 70-77.

    Three cases:
      - payload present, ws_connected=True  -> a successful poll
      - payload None                        -> a FAILED poll: ws stays True (the
        socket is fine, only the health data is unknown), everything else falls
        back to False/None
      - ws_connected=False                  -> the socket closed; the caller
        passes the last CACHED payload so the FSM keeps the fc1 timestamp it
        needs to judge chamber-dark

    Never raises, whatever the bridge sends (T-63-10).
    """
    if not isinstance(payload, dict):
        return {
            "ws_connected": ws_connected,
            "ros_connected": False,
            "humidifier_last_msg_ts": None,
            "fc1_last_msg_ts": None,
            "now_ms": now_ms,
        }
    return {
        "ws_connected": ws_connected,
        "ros_connected": bool(_dig(payload, "ros", "connected")),
        "humidifier_last_msg_ts": _dig(payload, "humidifier", "last_msg_ts"),
        # Phase 46 D-02: null when /health has no fc1 block (old bridge) --
        # graceful degradation, consumed downstream as "no signal", never "dark".
        "fc1_last_msg_ts": _dig(payload, "fc1", "last_msg_ts"),
        "now_ms": now_ms,
    }
```

```python
class _FakeConnect:
    """Scripted stand-in for websockets.connect.

    outcomes: list of either an exception (connect fails) or a list of frames to
    yield before the connection closes.
    """

    def __init__(self, outcomes):
        self.outcomes = list(outcomes)
        self.attempts = 0

    async def __call__(self, url):
        self.attempts += 1
        outcome = self.outcomes.pop(0) if self.outcomes else OSError("exhausted")
        if isinstance(outcome, Exception):
            raise outcome
        return _FakeSocket(outcome)


class _FakeSocket:
    def __init__(self, frames):
        self.frames = list(frames)

    async def __aenter__(self):
        return self

    async def __aexit__(self, *exc):

    def __aiter__(self):
        return self
```

- `__init__(self, *, config, http, on_message, on_liveness, log=None, connect=None,
  sleep=None, clock=None)` — stores everything; `connect` defaults to the real
  `websockets.connect`, `sleep` to `asyncio.sleep`, `clock` to `lambda: int(time.time()*1000)`.
  Injection is what makes the tests above socket-free. It must NOT build an `httpx.AsyncClient`.
- `ws_connected` / `ws_last_connected_ms` read-only properties.
- `async def poll_health(self)` — GET `config.bridge_health_url`, `raise_for_status()`, cache the
  body in `self._last_health`, and emit `parse_health(body, clock())`. On ANY exception: log a
  warning and emit `parse_health(None, clock())`. Mirrors `SignalClient.ensure_groups_loaded`.
- `async def run(self)` — the reconnect loop:
  ```
  backoff = MIN_BACKOFF_MS
  while True:
      try:
          async with connect(config.bridge_ws_url) as sock:
              self._ws_connected = True
              self._ws_last_connected_ms = clock()
              backoff = MIN_BACKOFF_MS           # reset on success (js:49)
              await self.poll_health()
              health_task = create_task(self._health_loop())   # 10s cadence (js:56)
              try:
                  async for raw in sock:
                      try:
                          on_message(json.loads(raw))
                      except Exception:          # bad frame: log, skip, keep going
                          log.warning(...)
              finally:
                  cancel health_task; swallow CancelledError
      except asyncio.CancelledError:
          raise                                  # shutdown must propagate
      except Exception as e:
          log.warning("[bridge-client] connect failed: %s", e)
      # closed or failed
      self._ws_connected = False
      on_liveness(parse_health(self._last_health, clock(), ws_connected=False))
      await sleep(backoff / 1000)
      backoff = next_backoff_ms(backoff)
  ```
  Note the ordering: wait the CURRENT backoff, THEN advance it — that is what produces Node's
  1,2,4,8,16,30 sequence. Advancing first would skip the 1s wait entirely.
- `asyncio.CancelledError` must propagate out of `run()` so boot.py's
  `except asyncio.CancelledError: pass` sees it.
