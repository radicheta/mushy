## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| farmer phone → signal-cli /v1/receive | Untrusted human input; messages can be arbitrary text. Phase 36 only matches `/ok|...|/i` — no parsing of arbitrary content here |
| Claude → /v2/send | Trusted (Claude is operator-controlled in this phase). Recipient list is hard-pinned to farmer #1 / #2 from operator |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-05 | Spoofing | Farmer reply attribution | accept | signal-cli /v1/receive populates `envelope.sourceNumber` from the Signal protocol; spoofing requires compromising Signal infrastructure — out of scope |
| T-36-06 | Information disclosure | Committed receive-*.json files | mitigate | All E.164 numbers redacted before commit (sed pass in step 6); message bodies retained as attestation evidence (no PII concern — they're "ok" replies) |
| T-36-07 | DoS | Polling /v1/receive in a tight loop | accept | Poll interval is 30s; signal-cli has no rate-limit issues at this cadence based on Phase 25 experience |
</threat_model>
