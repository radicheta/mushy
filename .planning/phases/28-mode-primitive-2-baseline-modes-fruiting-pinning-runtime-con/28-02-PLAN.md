    ```yaml
    # Phase 28: Mode primitive (D-01..D-06). Dotted-key flat params per D-03 — rclpy has no
    # native dict params; adding a NEW named mode beyond fruiting/pinning is a deploy in v0.
    # Active mode resolves to ModeView in fc_controller._resolve_active_mode (plan 03).
    fc_controller:
      ros__parameters:
        active_mode: fruiting
        # Fruiting v0 — D-05 — preserves Phase 27 HUMID-04 narrow-band PID behavior
        modes.fruiting.target_humidity: 0.96
        modes.fruiting.band_low: 0.945
        modes.fruiting.band_high: 0.975
        modes.fruiting.defend_side: both
        modes.fruiting.t_target: .nan
        # Pinning v0 — D-06 — passive only; defends floor 0.90 only, ceiling 0.99 silent (D-07)
        modes.pinning.target_humidity: 0.85
        modes.pinning.band_low: 0.90
        modes.pinning.band_high: 0.99
        modes.pinning.defend_side: low
        modes.pinning.t_target: .nan
    ```

    Critical YAML notes (verified pyyaml + ROS2 launch behavior):
    - `.nan` (lowercase, leading dot) is the YAML 1.1 NaN literal that pyyaml parses to `float('nan')`. Do NOT use `NaN` or `nan` — pyyaml interprets those as strings.
    - The dotted keys (`modes.fruiting.band_low`) must remain literal strings; YAML does NOT auto-nest them. rclpy reads them as flat parameter names — exactly what plan 03's `get_parameter('modes.fruiting.band_low')` expects per D-03.
    - `defend_side: both` is parsed as a STRING (not a YAML keyword); same for `low` (validate this in plan 04's on_set_parameters_callback against the enum {low, high, both}).
    - The new `fc_controller:` block is a SECOND scope — when the launch loads `fc_config.yaml`, both `/**:` and `fc_controller:` apply to fc_controller; `fc_controller:`-scoped values take precedence for any duplicates (verified: ros2/rclcpp last-section-wins for same-node scopes within one file).

    Why `active_mode: fruiting` and not just relying on D-04 fallback: explicit declaration means `get_parameter('active_mode')` works on first boot with no surprises; D-04's fallback kicks in only when the entire `modes.*` tree is missing (e.g. someone strips the block from a private fork).
