# Phase 12 — UI Design Contract

> Visual and interaction contract for Phase 12: Subscriber-Aware Camera.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

Phase 12 is primarily a backend change (ROS2 Python + Node.js bridge). The UI surface is narrow: the existing camera view in the OpenMCT Mission Control plugin (`src/mission-control/frontend/plugins/fruiting-chamber/plugin.js`). No new pages, no new routes, no component library. The contract below governs only what changes in that view.

**UI hint trigger (from ROADMAP.md):** The camera view must not show a broken image or stale error when fc_camera is in idle mode. It must convey "idle — not disconnected" to the operator.

## Color

Inherits OpenMCT dark theme. The camera view already uses these values (confirmed in `plugin.js` and `plugin.css`):

| Role | Value | Usage | Source |
|------|-------|-------|--------|
| Dominant (60%) | `#000000` | Camera view background, page background | `plugin.js` line 316 `background:#000` |
| Secondary (30%) | `rgba(0,0,0,0.2)` | Telemetry cards, panel surfaces | `plugin.css` `.temperature-display` background |
| Accent (10%) | `#4ecdc4` | Idle/active status badge border and dot — ONLY these two elements | `plugin.css` humidity display color; extended here |
| Destructive | not applicable | No destructive actions in this phase | — |

Accent reserved for: the stream status badge border (`#4ecdc4` when active) and the status indicator dot. No other elements.

Idle state badge uses `#555555` (mid-grey) border and dot — distinct from accent, signals reduced activity without implying error.

Error state uses `#888888` for paragraph text — matches existing error paragraph color in `plugin.js` line 321 `color:#888`.

## Interaction Contract

The camera view must express three distinct states. These replace the current binary (image showing / image broken) with a three-state model.

| State | Trigger | Visual Treatment |
|-------|---------|-----------------|
| **Idle** | fc_camera is in idle mode (no MJPEG subscribers; bridge has unsubscribed) | Status badge: grey dot + "IDLE · 1 frame/hr". Last known frame shown at reduced opacity (0.5) if available, otherwise empty state copy. |
| **Active** | Bridge has subscribed; frames arriving at 1 fps | Status badge: accent dot + "LIVE". Image at full opacity (1.0). |
| **Error** | `<img>` onerror fires (bridge down, camera disconnected) | Image hidden. Error paragraph shown in `#888`. No status badge. |

**Status badge spec:**
- Position: absolute, top-right corner of camera container, 8px inset
- Size: auto-width, 24px height
- Padding: 4px 8px
- Border-radius: 4px
- Background: `rgba(0,0,0,0.6)`
- Border: 1px solid — `#4ecdc4` when LIVE, `#555555` when IDLE
- Dot: 8px circle, same color as border, 4px right margin
- Font: 11px, weight 600, letter-spacing 0.05em, text-transform uppercase

**Implementation note:** The current `plugin.js` camera view is built via `container.innerHTML` string concatenation (vanilla JS DOM). The status badge must follow this same pattern — no framework, no external dependencies. The bridge already logs `[camera] MJPEG client connected/disconnected` — the status badge state is inferred from whether the MJPEG stream `<img>` is receiving frames, not from a separate API call. Detecting idle vs. active in the frontend: poll `Date.now() - lastFrameTimestamp`; if > 10 seconds with no new frame boundary, flip to IDLE badge.
