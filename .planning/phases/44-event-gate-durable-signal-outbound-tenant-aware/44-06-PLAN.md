<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed YAML → public git | tenant config becomes visible to anyone with repo access |
| secrets.env → alerter process | runtime secrets injection path; must never cross into git |
| TENANT_ID env → file system | path traversal risk if attacker controls TENANT_ID |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-06-01 | Information Disclosure | Secret accidentally committed to tenants/mossrock/config.yaml | mitigate | Task 6.1 acceptance criterion greps for PASSWORD/API_KEY in the committed YAML and fails if present; Plan-00 .gitignore rule blocks secrets.env |
| T-44-06-02 | Tampering | Path traversal via TENANT_ID='../etc/passwd' | mitigate | loadTenantFile uses `path.join` with a fixed base; planner adds a sanity check that resolved path stays under `tenants/` (e.g. `if (!resolved.startsWith(tenantsBase)) return {}`) |
| T-44-06-03 | Information Disclosure | config.js logs the loaded YAML at debug level revealing structure | mitigate | Existing config.js does not log; do not add logging in this refactor; secrets resolve from env via mustEnv() (never logged) |
| T-44-06-04 | Denial of Service | Malformed YAML in tenants/mossrock/config.yaml halts alerter boot | mitigate | loadTenantFile try/catch returns `{}` and logs a warn — alerter continues with env+defaults (graceful degradation) |
</threat_model>
