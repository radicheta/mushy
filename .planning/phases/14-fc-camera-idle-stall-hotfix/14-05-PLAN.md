This is a 30-minute timed sequence. Each phase of the sequence has an expected /health observation that proves the fix works. Instead of tail-following for 30 min, script the observations and sleep between them so the evidence is timestamped and tight.

Open a scratch file locally (use Write tool) at /tmp/soak-14.log and APPEND each block as you go. This file feeds into Task 3.

MINUTE 0 — establish baseline (MC closed, fc_camera should be idle).
```
date -u --iso-8601=seconds
curl -s http://localhost:8081/health | jq -c
ssh fc1-ts 'journalctl -u fc-core --since "3 minutes ago" --no-pager | grep fc_camera | tail -5'
```
Expected: subscribed=false, last_frame_age_sec is null or large. Journal shows the fresh "FcCamera node started" line from Task 1.

MINUTES 0..5 — sleep 300.

MINUTE 5 — simulate MC open by hitting the MJPEG endpoint. This is the canonical "viewer connect" event.
```
# Start a long-running MJPEG client in the background (600s = 10 min window)
(timeout 600 curl -s -o /dev/null http://localhost:8081/camera/mjpeg &) ; sleep 2
# Within 10s of that request the bridge should subscribe and fc_camera should ramp up
date -u --iso-8601=seconds
sleep 10
curl -s http://localhost:8081/health | jq -c
```
Expected: subscribed=true, last_frame_age_sec is a number and <10. Critical success marker #1.

MINUTE 6..15 — active window (10 min with viewer held open). Sample /health every 2 min.
```
for i in 1 2 3 4; do
  sleep 120
  date -u --iso-8601=seconds
  curl -s http://localhost:8081/health | jq -c
done
```
Expected every sample: subscribed=true, last_frame_age_sec <5. No stall during active.

MINUTE 15 — simulate MC close (kill the background curl). Bridge should unsubscribe after grace.
```
pkill -f "curl -s -o /dev/null http://localhost:8081/camera/mjpeg" || true
sleep 8    # > fc_camera grace (5s) + bridge propagation
date -u --iso-8601=seconds
curl -s http://localhost:8081/health | jq -c
ssh fc1-ts 'journalctl -u fc-core --since "1 minute ago" --no-pager | grep fc_camera | tail -5'
```
Expected: subscribed=false, journal shows "fc_camera: idle (0.000278 fps)" transition.

MINUTE 15..20 — deliberately exercise the stall condition — sit in idle for 5 min with no viewer.
```
sleep 300
date -u --iso-8601=seconds
curl -s http://localhost:8081/health | jq -c
```
Expected: subscribed=false, last_frame_age_sec increases monotonically. No journal transitions.

MINUTE 20 — the canonical stall test: re-open MC. Before the fix, this is where the stall would show. After the fix, recovery in ~1s via the 1Hz graph-poll.
```
(timeout 300 curl -s -o /dev/null http://localhost:8081/camera/mjpeg &) ; sleep 2
date -u --iso-8601=seconds
# Sample /health three times at t=2s, t=6s, t=10s after the request
for dt in 2 6 10; do
  curl -s http://localhost:8081/health | jq -c
  sleep 4
done
ssh fc1-ts 'journalctl -u fc-core --since "1 minute ago" --no-pager | grep fc_camera | tail -5'
```
**CRITICAL SUCCESS MARKER #2 — this is the whole point of the phase.** Expected: within 10s, subscribed=true AND last_frame_age_sec < 10 AND journal shows "fc_camera: active ... subscriber(s)" (the new log line from plan 14-02 Task 2).

MINUTE 22..30 — stability window. Sample every 2 min to make sure no flapping (active->idle->active->... would indicate grace-period interaction bug).
```
for i in 1 2 3 4; do
  sleep 120
  date -u --iso-8601=seconds
  curl -s http://localhost:8081/health | jq -c
done
pkill -f "curl -s -o /dev/null http://localhost:8081/camera/mjpeg" || true
```
Expected every sample: subscribed=true, last_frame_age_sec <5. Journal shows no further transitions (just the single active-at-minute-20 line).

END — confirm fc-core still healthy.
```
date -u --iso-8601=seconds
ssh fc1-ts 'sudo systemctl is-active fc-core'
ssh fc1-ts 'journalctl -u fc-core --since "35 minutes ago" --no-pager | grep -E "active|idle|error|FATAL" | grep fc_camera'
```

Save all output (every block) to /tmp/soak-14.log in append mode as you run it. Task 3 turns this into the evidence file.
