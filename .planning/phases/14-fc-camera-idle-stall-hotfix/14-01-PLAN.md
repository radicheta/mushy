We cannot inject code into the running fc_camera process directly. Instead, spawn a SHORT-LIVED rclpy probe participant on fc1 that joins the same DDS graph and calls `node.count_subscribers('/fc1/camera/compressed')` from a fresh node. This gives us "what the node-level graph cache reports right now" — the number we'd get if fc_camera were to call it on its own node (which, per Open Question #2 in research, is the remaining unknown).

Create a single-file Python probe at `/tmp/fc_camera_probe.py` on fc1 via SSH and run it. The probe MUST terminate in under 10 seconds.

```bash
ssh fc1-ts 'cat > /tmp/fc_camera_probe.py <<PYEOF
import rclpy
from rclpy.node import Node
import time

rclpy.init()
probe = Node("fc_camera_probe_14_01")
# Give DDS discovery a moment to populate the node-level graph cache
time.sleep(3.0)
n_subs = probe.count_subscribers("/fc1/camera/compressed")
n_pubs = probe.count_publishers("/fc1/camera/compressed")
print("PROBE_RESULT count_subscribers={} count_publishers={}".format(n_subs, n_pubs))
probe.destroy_node()
rclpy.shutdown()
PYEOF
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=69 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp CYCLONEDDS_URI=file:///etc/cyclonedds-tailscale.xml
timeout 15 python3 /tmp/fc_camera_probe.py
rm -f /tmp/fc_camera_probe.py'
```

Capture the `PROBE_RESULT count_subscribers=N count_publishers=M` line. Expected on live stall per H1: count_subscribers=1 (the bridge), count_publishers=1 (fc_camera).
